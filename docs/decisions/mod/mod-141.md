## What the maintainer can do now

A step graph of any scope (project, workspace, global library) is built and saved in one rataflow editor:

- steps and their links;
- `if` predicates;
- loop limits;
- splits (none, divide, compete behind a switch);
- the palette;
- plan scope;
- the deadline and judge;
- candidates.

It never needs seeds or SQL. `Settings > Kinds` opens it on a project's graphs. `GraphEditorHost` is the
scope-generic entry point that MOD-124 wires into the Toolbox for workspace and library graphs.

## M1 - editor core (`a040804e`, 2026-11-10)

- **Where:** `crates/htui/src/ui/graph_editor/`: the rataflow canvas, the node form with candidates, the edge form
  with a live `if` parse, the links list, and a client-side validator in the store's order.
- **Undo and redo:** each applied edit is one `ReplaceGraph` CAS on `step_graph.revision`; a `Stale` answer
  reloads and clears both stacks.
- **Kinds:** opens it on `Enter`, and the old position-based phase forms are retired.
- **Store worker:** `ReplaceGraph` answers `GraphReplaced` with the body, and `GraphBody` reads one graph of any
  scope.
- **Keys:** `[graph_editor]` and `[graph_editor.links]`, with no F-keys.
- **Review R1:** fixed undo past a refused entry, a landed write read as failed, and a gesture outliving the
  canvas.

## M2 - splits, palette, deadline and judge, header (`427f7690`, 2026-11-12)

- **The step form now edits:**
  - the split: none, divide, or compete. Compete is offered only while the new App-rung switch `compete_fan_out`
    is on; while it is off a compete step is read-only and kept byte for byte.
  - fan-out, the judge, the deadline, the palette flag and plan scope;
  - the divide columns, and the default parts through a part form (`alt-e`). A part key refuses `/` and `@`.
- **Model and stores:** `StepGraphPhase` carries `deadline_seconds`, `judge_agent_id` and `judge_model`. Both
  stores write them, and resolve reads the step first.
- **Warnings:** `notes` gives resolve's own sentences as warnings that never block a save; the canvas marks a noted
  step `! name`.
- **Header:** shows the run limits read-only (`run_bounds`).
- **Owed:** tightening the limits and the `runtime_changes` override are MOD-171; review follow-ups are MOD-172,
  MOD-173 and MOD-174.

## M3 - every scope, and the picker fix (2026-11-12)

### Maintainer decisions (at planning)

- **M-1:** a workspace graph's label always names its workspace (`flow · workspace Platform`), so it doesn't change
  when a sibling appears.
- **M-2:** a typed graph label resolves when it names exactly one graph. When it names two or more it is refused,
  and the refusal lists the qualified labels.

### What landed

- **Labels** (`catalogue::WorkspaceNames`):
  - A project graph reads by its bare name, and a library graph as `name · library`.
  - A workspace graph reads `name · workspace <name>`. It uses the slug instead when another listed workspace has
    that name, or uses it as its slug.
  - A workspace whose row was not read keeps the bare `· workspace`. A failed read is logged and falls back, never
    failing the reply (R1 L3).
  - `catalogue::snapshot` reads each workspace once per call and labels alike across every project of the scope
    (R1 L2).
  - `item_writes` fills the names on the `ItemForm` and `Diverged` answers only, so mint and edit read nothing
    extra.
  - The item form's graph picker, the divergence view and every Kinds line label through the context they read.
    The free `graph_label` is gone.
- **Typed resolution in Kinds** (`graph_named`):
  - An untouched prefilled field keeps the kind's graph.
  - Otherwise the text is matched against the shown label and both qualified spellings (name and slug, R1 M1).
    Next comes a bare name, or the old `name · workspace`.
  - One match resolves. Several are refused with `ambiguous_graph`, `"flow" names 2 graphs; type one of: …`.
    Choices that would still read alike get a short id suffix (R1 L5).
- **`GraphEditorHost`** (`ui/graph_editor/host.rs`):
  - `open_by_id` reads `GraphBody` and `Personas`. `with_body` wraps `GraphEditor::open` for a host holding the body
    (Kinds).
  - It routes the editor's replies and passes keys, mouse, paste and render through.
  - A refused read retries on reactivation and opens when the body arrives. Not-found is final (R1 L1).
  - Opened by id, it re-reads personas on activation (R1 L4).
  - Kinds' `Mode::Graph` holds the host, and its duplicated reply arms are gone. Kinds still edits only project
    graphs; the Toolbox call is MOD-124's.

### Review

The configured `rust-reviewer` found no Critical or High issues: reply routing under the Settings broadcast,
`Send`, and Debug hygiene all held. It found one Medium and six Lows. All were applied except one part of L1:

- **Deferred (maintainer, 2026-11-12):** `StoreReply::GraphBody` carries no id. A late `GraphBody(None)` or
  `Failed{"graph_body"}` from a replaced open can therefore refuse a newer one. Owed to MOD-124, which opens by id.

### Known limits

- A label with an id suffix (the L5 fallback) only tells two choices apart; it cannot be typed back in.
- The real `store.workspace` error path inside `WorkspaceNames::read` is untested, because there is no failing
  `WriteStore` fake; `from_reads` is tested instead.
