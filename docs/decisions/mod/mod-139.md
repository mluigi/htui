## What a divided node does now

A `divide` node expands into `<name>:plan` (planner) and `<name>` (integrate), as MOD-138 froze it.

1. **Admission.** The planner admits its default parts in one transaction (`WriteStore::admit_plan`):
   - revision 0 is `admitted`, with `base_refs` set to the primary HEAD per repo;
   - every part row is `pending`, with role `part`, `parent_step_id` the planner, and `node_key`
     `<divided>/<key>`;
   - the planner moves to `done`.

   Every refusal is decided before the first write, and caps are counted at every admission.
2. **Parts.** Each part runs in its own tree from `base_refs`, with:
   - its own internal `part` prompt section, agent and session;
   - no verify and no landing.

   Under `shared_serialized` the parts run one at a time, with resets to base around each. `fan_out_only` exposes
   `command_run` to any session with live siblings.
3. **Inputs.** Part documents are left out of generic input resolution on all three stores, so N parts writing one
   kind never shadow each other downstream.
4. **Retries.** A failed part retries alone, at its own position. An exhausted part fails the divided step
   (`part_exhausted`), which then takes the integrate node's `fails` edge or ends the run. A loop back over the node
   retires its parts and abandons its plans before the planner row, so a cut-short retirement replays.
5. **Integrate.** Integrate prepares from `base_refs`.
   - **Pre-merge.** `Isolator::premerge` merges the done parts in plan order. In copy mode it first copies each
     part's commits into integrate's copy (`copy_range`) and labels `htui/<part>` there. Each repo stops at its
     first conflict, which is aborted.
   - **The agent's inputs.** The pre-merge report reaches the agent twice: as a protected `premerge` prompt
     section (conflict paths capped at 20) and as an item note. The trimmable `parts` section carries each part's
     document and diffstat.
   - **The agent's job.** It finishes the merges and writes the divided node's output.
6. **Post-check.** After the session, `Isolator::unmerged` checks every committed part:
   - its tip must be an ancestor of integrate's capture;
   - its changed paths must overlap integrate's own (Confirm 2, against an `-s ours` merge).

   A part that fails either check settles `integrate_incomplete`. The settle ranks it after `missing_output` and
   before `verify`.
7. **Landing.** Only the integrate branch lands, through the unchanged single-branch reconcile. The orchestrator
   itself never resolves a conflict.
8. **Recovery by role.**
   - **Planner:** a planner with an admitted plan is done. Without one, it re-admits on the same row.
   - **Part:** a part follows the plain-step artefact test; one whose tree must not be reset parks the node.
   - **Integrate:** recovery post-checks before landing. A read error there fails the run as the walk would
     (R-6).
   - **Per mode:** worktree and copy re-prepare; a clean in-place checkout resets to base; a dirty one parks.
9. **Resolve.** Resolve runs default-parts divided nodes. It refuses:
   - a planner agent (`NotRunnable::PlannerAgent`, MOD-140);
   - a node with no default parts (`NoParts`);
   - a plan scope other than `parts` (`PlanScope`);
   - every admission refusal decidable from the snapshot (`ResolveError::DivideRefused`, worded as the run failure
     would be).

   M2's test-only seam is gone; divided cases run through the real enqueue.
10. **Answers on an integrate park.** Approve and Skip re-run the post-check and are refused while a part is
    unmerged. Promote is refused on every integrate row (R-1). The refusals name Retry or Reject (R-5).

## Milestone 2: planner admission and parts (2026-11-11)

**What was built:** admission (`admit_plan`, `abandon_plans`, `PlanStatus::can_move_to`) and the engine reading rows
by role (`node_of`, `node_at`, `EngineError::RoleRow`). Also:
- a pure `divide.rs`;
- `Cursor::Parts`, with `drive_parts` and `run_part` (a hand-written `FuturesUnordered`, because `buffer_unordered`
  broke the `Send` assert);
- seven `RunFailure` variants;
- per-part retries, the planner branch of `settle_failed`, and recovery per role.

**Rulings:**
- F-1: an interrupted part spends an attempt.
- F-2: divided runs exist in engine cases only until M3.
- F-3: the store refuses an empty admission.
- F-4: `plan_digest` hashes a canonical, key-sorted form, because `preserve_order` is on.
- F-5: one planner admits at a time.
- F-6: a not-reset part keeps its node parked.
- F-7: a parts round stops pulling after a cancel, a lost fence or a refusal.
- F-8: parts and plans are retired before the planner row.

**Review:** `rust-reviewer` found one high, two medium and two low; a verifier per finding narrowed them. Fixed: F-7
(lowered from high to medium) and F-8 (low). Deferred to M3, which settled the first: the `shared_serialized`
end-of-round reset was best-effort (integrate prepares from base). Kept as is: substitution notes are at-least-once
on a re-admission, as `admit_indices` is. The workspace gate also found a stale scrubber-site pin
(`prompt_digest`), fixed.
