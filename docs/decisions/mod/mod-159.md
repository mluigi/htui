## What the maintainer can do now

Each Qdrant collection has exactly one indexer at a time: the htui process (an `htui worker` or a TUI) that holds its
lease row in Postgres. Every workspace has its own collection (`htui_ws_<uuid>`), and global memory will live in
`htui_global`. A new or edited item, requirement, item document or owner document is searchable within a minute.
`Ctrl+R` in the knowledge-search overlay and `htui --index-items` index a workspace at once when nobody else does;
when another box holds the lease, they ask that holder to reindex and say which box it is:
`indexing runs on hal (lease until 09:41); asked it to reindex`. Quitting a TUI or a worker lets its leases go.

## M1 - lease and collections (2026-11-14, `cd65d461..a61f879b`, merged on main 2026-11-14)

- **Lease table:** migration `0038_indexer_lease` (`0036` on the branch, renumbered behind MOD-122 M3's and MOD-125
  M4's at the merge), one row per collection (holder, box, expiry, and `pass_requested_at`, reserved for M3). Not
  mirrored into the SQLite cache: it is live coordination state. Store seam `IndexerLeaseStore` (MemStore, PgStore,
  `Backend`, refused offline); `INDEXER_LEASE_CASES` 10.
- **Lease times:** the run lease's (`LeaseTimes::from_app`: TTL 120 s, a 40 s beat by default). One owner token per
  process for indexing; the box is `this_box()`.
- **Collections:** `IndexedCollection { Workspace(WorkspaceId), Global }`, named `htui_ws_<uuid>` (UUID, never
  the slug, which can be renamed) and `htui_global`. They replace `htui_concepts_v2`, which the global holder drops
  once.
- **Index job:** the worker's and the TUI's index job reconciles under each collection's lease, for every
  collection. It renews before each delete batch and confirms orphans by re-listing them in the same pass.
- **Searches:** TUI, CLI and MCP searches read the workspace collections plus global. `--search-items` over several
  workspaces names those unavailable; MCP answers from the collections that work.
- **`Ctrl+R` and `--index-items`:** take a free lease, index and let it go; a live holder is named instead.
- **Review:** R1 (store: single-collection release, the lapsed-`Ours` case, a concurrent-take test, orphans
  confirmed by re-listing, the guard right before the delete) and R2 (htui: a per-press `Ctrl+R` lease, partial
  search answers, the job's keyring read only when due, and a box that cannot read the key lets its leases go).

## M2 - freshness (2026-11-14, `b4509a9f..d9020fcf`, merged on main 2026-11-15)

- **Change read:** `IndexChangesStore` (MemStore, PgStore; no migration, two `.sqlx` entries) lists the items, item
  documents, requirements and owner documents written after a store-clock instant; `INDEX_CHANGES_CASES` 7.
- **Incremental sync:** `Indexer::sync_changes` rebuilds only those rows and deletes only their stale points, under
  the lease guard. Deleted rows stay with the full reconcile.
- **Cycle:** the index job runs it every 60 s (`INCREMENTAL_CYCLE`, a constant) per held collection, from an
  in-process cursor pulled back by `cache_overlap_seconds`, with no keyring read. A full reconcile still runs every
  `concepts_sync_minutes`. A new holder reconciles in full first.
- **Review:** R1 pinned the change read's project filter and the amend equality (`d9020fcf`).

## M3 - pass requests and holder visibility (2026-11-15, `c9edd91a..cfa8d817` on `hr/MOD-159`)

- **No migration:** the `indexer_lease.pass_requested_at` column was already in `0038`. `TABLES` stays 60, store
  conformance `CASES` stays 343, and the table stays not mirrored.
- **Store (T1, `ce4961a6`, `bc636248`):**
  - `IndexerLeaseStore::request_indexer_pass(collection)` stamps a request with the store clock, but only when
    someone holds the lease live, and answers that holder;
  - `claim_indexer_pass(collection, owner)` clears the request on the holder's row and answers whether one was
    pending;
  - a take or a release keeps the request; only a claim clears it.
  - `take_or_request_pass` (htui-core, 3 attempts) answers `LeaseTurn::{Ours, Requested(holder), Held(holder)}`: a
    free or lapsed lease is taken, a live holder is asked, and `Held` means nothing was recorded.
  - Two new `.sqlx` entries (568 in all). `INDEXER_LEASE_CASES` 10 → 15 (five pass-request cases, pinned in
    `mem_store.rs` and `pg_conformance.rs`).
- **The holder serves requests (T2, `41c1594d`, `bf2b5574`):** right after its beat's take on a held workspace
  collection, the index job claims a request and, if there was one, reconciles that collection in full that beat,
  whatever `concepts_sync_minutes` says. The claim comes before the pass, so a request made during the pass waits
  for the next beat. A failed requested pass has consumed its request; the interval and the next request are the
  retries (a down Qdrant must not turn into a full reconcile every beat). The global collection is never claimed.
- **`--index-items` asks (T2):** for a workspace held elsewhere it prints `workspace <slug>: indexing runs on <box>;
  asked it to reindex`, skips it and still exits 0. The old `…; not indexed here` note stays for `Held`.
- **`Ctrl+R` asks (T3, `1320d744`, `ca52f45f`):** `IndexOutcome::Requested`, and the overlay draws the requested
  line dim (new snapshot `requested_from_another_box`; `held_by_another_box` unchanged).
- **One press token per TUI runtime (T3):** `ConceptsRuntime::press_owner`, minted once, replaces the per-press token.
  A second press takes back a superseded press's lease on the same workspace as its own. Quit lets the press leases
  go beside the job stop (`tokio::join!`, so the concepts teardown stays within 2 s).
- **Docs:** `docs/htui-worker.md`, `docs/htui-cli.md` and `README.md`.
- **Review:** rust-reviewer approved with 9 low findings, all fixed in R1 (brief `5fd09ee3`, fixes `2025c1e9`,
  `cfa8d817`):
  - L1: the superseded press is aborted before the new one spawns and awaited first, so its release cannot land after
    the new press's take;
  - L2: the exit's press leg gives the aborted tasks half of `TUI_RELEASE_WAIT` and always tries the release in the
    rest;
  - L3: `LeaseTurn::Held` names the holder the last take saw (possibly lapsed);
  - L4: a beat test that could not fail was removed rather than wrapped (the counting wrapper would forward about 55
    store methods);
  - L5: a test pins that the global collection's request is never claimed;
  - L6/L7: docs say who reconciles a request and what happens to a superseded press on another workspace;
  - L8: the quit-mid-sync test proves the press token holds the lease;
  - L9: the claim line says "reconciling this beat"; a doc comment rewrapped.

## Accepted residues

- A request made while a one-off run (`--index-items` or a `Ctrl+R` press) holds the lease waits for an index job to
  take the lease; that job's first beat reconciles in full anyway.
- The `LeaseTurn::Held` exhaustion path (the lease changes hands at every one of the 3 attempts) has no
  deterministic case.
- A Postgres release already sent when a superseded press is aborted could still commit.
- `Ctrl+R` presses from two different TUI views on the same workspace share the press token, so one can release the
  other's lease. Noted by the R1 implementer, not fixed; a candidate follow-up.
- From M2: document `created_at` is the writer's clock, so a writer lagging the database by more than the overlap
  waits for the reconcile; a pass with changes reads the changed project's points from Qdrant each cycle while a
  write stays in the overlap; `document` has no `created_at` index.
