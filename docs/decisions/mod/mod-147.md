## What the maintainer can do now

A workspace owns things of its own through one hidden **scope row** in `project` (`@<workspace-slug>`, type
`workspace`):
- its own `WS` items (plan, then a hard-gated review), keyed `@shop:WS-1`, created with `N` on the Backlog's
  workspace group;
- links from member-project steps to them;
- its own documents, such as `goals`, written and read in Settings › Hierarchy (`o`);
- a secret scope, bound from Settings › Secrets;
- a folder on each box (`~/workspaces/<slug>` by default).

Search covers all of it: the TUI search overlay, `htui --search-items` and the indexer cover the member projects
plus the scope row. A project's own documents are searchable too. No per-project read path learned a second
owner.

## M1 - the scope row and owner documents in the store (2026-11-09, merged `50f9ebe6`)

- **Scope row:** every workspace has one, created with the workspace and by the bootstrap. It is seeded with `WS`.
  `@` slugs are reserved. The row never joins `workspace_project`, so no lister shows it.
- **Owner documents:** `OwnerDocument` rows with `document.project_id` and a null `item_id`, kept apart from
  item documents. Versions are per `(owner, kind)`.
- **Folder:** `workspace_box_path.folder_path`, default `~/workspaces/<slug>` (one-name slugs only).
- **Delete:** a workspace delete cascades its scope row, with counted reach and a mirror rebuild. It is refused while
  a scope-row run is live (stopped included). `delete_project` refuses a scope row.
- Migration `0026_workspace_scope`, cache `0009`; store conformance `CASES` 247.

## M2 - keys and links across a workspace (2026-11-11, merged `93e3cbbd`)

- **Qualified keys:** `slug:KEY` / `@<ws>:KEY` (`htui_core::model::key`, `KeyQualifier`); a bare key means the
  caller's own project. `item_by_key` resolves them; MCP `item_link` takes them and answers a canonical `to`.
- **Links:** `propose_link` reaches the step's workspaces' scope rows and their members (`link_outside_reach`).
- **Prefixes:** a scope-row kind may not take a member's prefix (`workspace_prefix_taken`). A colliding project
  still joins, with a Settings notice (`HierarchyJoined.shared_prefixes`).
- **Runs:** scope rows use their workspace's graphs, and their runs carry its `workspace_id`.
- **Waiting:** the waiting list and `htui waiting`/`status` (whole workspace only) read the scope row and qualify
  shared prefixes. `--json` adds `project` and `qualified_key`.
- `CASES` 255. Kept by decision: MCP `remove` tells an existing out-of-reach key (`not yours`) from a missing one.
  Waiting read cost became MOD-170.

## M3 - TUI surfaces (2026-11-13, `0dc19385..00c7c66b`)

- **Backlog:** the scope row's items are a first group titled with the workspace (`StoreReply::Items { scope_row }`,
  drawn even when empty). `N` on it creates a `WS` item. The waiting overlay reveals workspace items.
- **Owner documents pane:** Settings › Hierarchy `o` on a project or workspace row (`owner_documents.rs`, context
  `settings.documents`). It lists documents per version, shows one, and writes a new document or version through
  `$EDITOR`. A workspace lists `goals` first. A refused or ambiguous write keeps the draft.
- **Secrets and folder:** Settings › Secrets has a workspace row that binds the scope row's secret scope. The
  workspace row and editor show the folder on this box.
- Review R1 fixed the folder's home source, the draft keeping and four test gaps.

## M4 - search (2026-11-14, `450dd6e1..f2d535f8`)

- **Owner-document points** (`htui-store` `vector.rs`): `Subject::OwnerDocument` and `Owner::Document`. A point is a
  `document` point with `document_id`, `doc_kind`, `doc_version` and `chunk`, and no `item_id`, `status` or
  `resolution`, so status and decision filters leave it out. Its key is the owner's slug (`@platform`, `htui`).
  `PAYLOAD_SCHEMA` went from 2 to 3, so each box's collection is dropped once and refilled from Postgres. The
  collection keeps its name (`htui_concepts_v2`).
- **Owner-document pass** (`vector_sync.rs` `sync_owner_documents`, beside the item loop, easy to move into
  MOD-159's indexer):
  - it indexes the newest version per kind;
  - a document is in step only when it holds a point for every section;
  - each document is written in one upsert;
  - a rebuild deletes the points it does not write again.
- **Workspace search scope:** `htui_store::vector_sync::workspace_search_scope` adds the scope row to a workspace's
  scope. A failed lookup is logged and leaves the scope unchanged. It is used by:
  - `scopes()` in `concepts.rs`, for `--search-items`, `--index-items` and the worker's index job;
    `--project @<ws>` narrows to the scope row;
  - the TUI concepts runtime, through `scope_row_of: Option<WorkspaceId>` on `SearchConcepts`/`IndexConcepts`.
    The search overlay sends it in "all projects" mode, and the reply echoes it.
- **Hits:** Enter on an owner-document hit keeps the overlay open with a notice pointing at Settings › Hierarchy.
  MCP maps it to `owner_kind: "project"`; the tool's scope stays the session's one project (MOD-112).
- **Review R1** fixed:
  - the overlay telling "all projects" from a cycled project in a one-member workspace, late replies included;
  - a half-indexed document never being completed;
  - the `@` slug error naming a workspace;
  - a double payload key.
  The fix-round verifier caught a regression in the half-indexed fix: extra points were kept and the document was
  rewritten on every sync. It was fixed in `f2d535f8`.
- Deferred by the maintainer: a test for `workspace_search_scope`'s failed-lookup fallback, which needs a fault
  seam in `MemStore`.
- Gate on the sandbox: green with the live-Qdrant step skipped (8797 tests).
