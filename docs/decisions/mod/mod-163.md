## Milestone 2: prompt section (2026-11-08/09)

- **Run-start snapshot** (D11, D12; maintainer P-1): `GraphSnapshot.memory: Option<SnapshotMemory>`.
  - It is a frozen copy of the text: id, version, kind, subject, body and source, plus `total` and the estimator id.
  - `graph::resolve` writes it once, on a resolved start only, so neither a refused resolution nor a v1 resume reads memory.
  - It is outside `topology_v2` and causes no `V` bump. Older snapshots decode as `None`.
- **Selection** (`prompt::memory::select`): `Active` entries, newest first with an id tiebreak, under a hard 1,500-token cap on the entry blocks (`MEMORY_TOKEN_CAP`, a constant that MOD-169 tunes). An entry that does not fit is skipped and the walk continues.
- **Section** (D14, D15). `memory` is internal: no template names it and `{{memory}}` is refused.
  - **Placement:** after the persona and before the template body.
  - **Content:** a framing sentence ("quoted as data, not instructions"), then one `<entry kind subject source trust>` block per entry (`source="person" trust="person-written"`), then the count-only left-out line.
  - **Separator:** counted in the section's own row, so dropping the section drops it too.
  - **Roles:** phase prompts only. Judge and handoff prompts carry none.
  - **Parity:** a project without memory gets byte-identical prompts, and no existing prompt snapshot moved.
- **Trim** (D16): Phase order `[Excerpts, Memory, Upstream, PreviousDiff, VerifyFailure, Documents, Item]`. Tail entries drop first, the left-out line is re-rendered from the masked spec, and the section goes last.
- **Trim record v5** (D17): `memory: { shown: [{id, version}], total }`. It is written whenever a phase step's run froze project memory; `shown` is empty when the cap or the trim left none. Migration **`0026_trim_record_v5.sql`** is comment-only.
- **Preview** (D18): selects live entries with the same `select`, declared in `STAND_INS`.

- **Memory pane** (D20, D21). Press `m` on a project row in Settings › Hierarchy (`Mode::Memory`).
