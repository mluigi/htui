## PRD gate (maintainer, 2026-11-13)

- **Model seam:** MOD-164 builds MOD-126's light-model key (`{agent_id, model}`); MOD-126 keeps only the
  run-start workflow pick.
- **Person against run:** a person's entry always wins; the run's write is dropped and the drop is noted.
- **Trigger:** failures and retries only (a failed step, a retried attempt, a failed verify, a gate rejection
  or retry). Measured wins wait for MOD-165.
- **Run record:** the capture is its own step row and never fails the run.
- **Budget:** a token cap (input 6,000, output 2,000) as constants MOD-169 tunes; the write cap is 3.
- **CONFIRM:** with no light model set, a failing or retried run gets a capture row passed as
  `skipped: no light model configured`.

## Milestone 1: the run write path

- **Migration `0033_memory_capture`** (Postgres only; memory is not mirrored):
  - `memory_entry` gains `source` (`person` | `run`), nullable `run_id`, `step_id`, `item_id`, `agent_id`
    (all `ON DELETE SET NULL`), `model`, `commit_hash`, `evidence` JSONB and the counters `shown_steps`,
    `shown_done`, `shown_failed`;
  - `chk_memory_entry_person_has_no_run`; partial indexes on `step_id` (the cap's count), `run_id` and
    `item_id` (the `SET NULL` scans);
  - `trg_memory_entry_updated_at` is recreated with a `WHEN` clause, so a counter-only update leaves
    `updated_at` (the prompt's newest-first key) alone;
  - `chk_run_step_stage` widens to `-4..-1` with the new stage key `capture` at -4.
  - Pins moved: migrations 30 -> 31; `TABLES` stays 52.
- **Model:** `MemorySource::Run` renders `trust="model-written"`. `MemoryEntry` gains `source`,
  `provenance: Option<RunProvenance>`, `evidence: Option<MemoryEvidence>` and `usage: MemoryUsage`. Postgres
  decodes through a flat `MemoryEntryRow`.
- **Write verb** `WriteStore::write_run_memory(fence, step, NewRunMemory) -> RunMemoryWrite`, on MemStore,
  PgStore, `Writer` and both worker twins. In one transaction (Postgres takes `FOR NO KEY UPDATE` on the step
  first, so the cap is serialized):
  1. fence;
  2. the step must be the capture stage (`memory_needs_a_capture_step`);
  3. evidence must be non-empty and cite only steps of the run (`memory_evidence_outside_the_run`);
  4. at 3 entries for the step, `CapReached`;
  5. a live entry on the same folded subject: a person's entry, or a run entry a person has amended
     (`version > 1`), answers `PersonHolds` and writes nothing; a run's entry is superseded and kept for audit.
  Provenance (run, step, item, agent, model, author `run.started_by`, box `run.lease_box_id`) comes from the
  rows, never from the caller; only `commit` and evidence come in.
- **Usage counters:** `finish_run` tallies, once, right after `legal_move` and in the same transaction, the
  entries each step's `trim_record` lists as shown and how those steps ended. Ids are counted once per step;
  malformed records count nothing.
- **Prompt and pane:** the prompt section freezes each entry's own source (person and run entries share one
  newest-first order under MOD-163's cap). The Memory pane gains a source column.
- Store conformance `CASES` 290 -> 300.

## Milestone 2: the extraction turn

- **Light-model setting:** `SettingKey::LightModel` (app rung only, `{agent_id, model}`; the model is trimmed
  to count and may not hold a NUL), `resolve_light_model`, and a Settings > Prompt "Light model" row cycling
  through enabled agents' models, then `not set`.
- **Snapshot:** `GraphSnapshot.capture: Option<SnapshotCapture>` (`#[serde(default)]`, out of the topology
  hash), frozen at resolve from `memory_capture` and the light-model setting. An older snapshot never
  captures.
- **Capture core** (`htui-core/src/capture.rs`): `capture_trigger` over non-stage rows; `EvidencePack`
  (labelled blocks under the 6,000-token input cap); `capture_prompt`; `parse_capture` (strict JSON, at most 3
  kept entries, every quote at least 12 characters and a substring of its block's evidence spans, never of
  htui's fixed label lines; subject, body and quotes scrubbed fail-closed; 2,000-token output cap).
- **Engine:** every terminal path (14 in `engine.rs`, 2 in `gate.rs` through a `RunEnd` trait) goes through
  `Engine::end_run`, which runs the capture (`engine/capture.rs`) before `finish_run`, and `finish_run` stays
  the last write.
  - The capture runs at most once per run, only while the run is live and has an item; a crash's leftover
    capture row (running or pending) is interrupted, never re-run.
  - The run's outcome is decided when `end_run` is entered: the walk is cut and admits nothing new, the
    session runs on the run's own control under a 10-minute deadline, and a second end of the run in the
    same engine waits for the first. A walk cut never cancels a capture; only the run's own cancel does, and
    a cancelled run never captures.
  - Any capture failure (timeout, refused or malformed output, uncited quotes, a store refusal) settles only
    the capture row, with an item note; the run ends exactly as it would have without memory.
  - Orch conformance `CASES` 234 -> 249.

## Review and fix round

`rust-reviewer` (two area instances) found two highs, both in the engine: a capture under a walk already cut
by a sibling read the cut as a cancel and left the run `running` (H1); a live capture ran while the walk kept
admitting siblings, and a second end interrupted it as a crash leftover (H2). Mediums: a person's amend of a
run entry was not protected (M1); a quote could cite htui's own label text (M3); a pending capture row left
by a crash was never settled (M4). All were fixed in F1/F2 with tests. The F1 verifier found a cut walk still
admitted new nodes (repaired) and, low, that an end waiting on a cancelled capture lost the cancel (fixed on
the main thread, `f9ca92bd`; no test, MemStore has no seam for it).

**Deferred:** `GateContext.end` stays an `Option` whose `None` arm only gate unit tests use; a stored
`evidence` value that does not decode fails the project's memory list (htui is the only writer).
