**Requirements:** `R-ENT-8`, `R-TUI-1`, `R-TUI-2`, `R-TUI-11`, `R-STO-8`, `R-ORCH-6`, `R-MCP-2`.
**Origin:** ANA-35 (`docs/ANA-35.md` §7.1 verdict, §7.10 migration order; the P1 spawn).
**Artifacts:** plan `.claude/plans/mod-144-item-status-reduction.plan.md` (Deltas Δ1-Δ10, Decisions
A-C, normative rules, verified-claims table of 26 rows), blueprint
`.claude/plans/mod-144-item-status-reduction.blueprint.md` (plan deviations PD1-PD18, full `0024`

## What was built

- **Stored status** (`htui-core` `Status`): `open | blocked | closed`. `can_move_to` allows only
  `open ↔ blocked`; `closed` is reached only through `close_out`, which is now the only writer of
  `closed_at`. `Status::is_terminal` is gone.
- **Derived display state** `ItemState` (nine values, `ALL` in attention order: needs you, failed,
  running, stopped, blocked, queued, open, done, closed) from `ItemState::of(status, latest)`, where
  the **latest graph run** is the newest `kind = 'graph'` run by `(queued_at, id)` with `cancelled`
  skipped (`latest_graph_run`, `latest_live_graph_run` over `RunFacts`). `latest_run_status` is
  appended to `ItemSummary`, `LinkNode`, `UpstreamEntry` and `QueueRow`; `ItemFilter.states` filters on
  it beside `statuses`.
- **No more mirroring.** The store's `create_run`, `claim_run`, `promote_step`, `park_step` and
  `finish_run` stop writing the item (`finish_run_item_mirror` deleted); the engine's seven mirror
  transitions (`cancel_queued`, `recover_run`, `park_interrupted`, `resume_window`,
  `park_selection`, `park_run`, `unpark`) are gone, and with them `cancel_queued`'s E-2 crash window.
  The blocking writes (`refuse_no_candidate`, `block_and_fail`, the review-loop escalation) move
  `open → blocked`; Unblock's FollowRun moves `blocked → open`, the parked run carrying "needs you".
- **One live graph run per item.** `startable(status, live)` (open and no live graph run; the live set
  includes MOD-125's `stopped`) is checked under the item's `FOR UPDATE` lock in `create_run`, by
  `start_enabled` and by `enqueue_with`; Postgres backs it with the partial unique index
  `uq_run_item_live`. The pre-run refusals (rung four, missing tags) block through
  `WriteStore::block_if_idle`, which takes the same lock and skips the block when another box has just
  created a live run (review finding M1: once `create_run` stopped writing the item, a plain
  compare-and-set could block an item another box was running).
- **Run-anchored rules, alike in Pg, the SQLite cache and MemStore.** Ready: open, no non-cancelled
  graph run, every live `blocked_by` target released (closed, or its latest graph run `done`; MOD-133
  adds "landed"). Waiting-on-you: blocked items or a run `awaiting_approval`. Queue prune: closed or
  finished. `queue_rows` keeps its own cancelled-inclusive LATERAL for `CancelledInBatch` and projects
  the non-cancelled `latest_run_status` beside it.
- **Close-out law** (replaces MOD-38 D1): refused while a run is live; `done` and `concluded` close
  only an **open** item whose latest graph run finished `done` (maintainer decision PD18: a blocked
  item is unblocked first); `rejected`, `withdrawn`, `superseded` and `duplicate` close an open or
  blocked item whatever its runs did. `Resolution::default_for(status, finished_output_kind)`:
  finished with a last phase whose `output_kind` is `verdict` → `concluded`, finished otherwise →
  `done`, else (or blocked) → `withdrawn`, read from the run's own `graph_snapshot`
  (`GraphSnapshot::last_output_kind`).
- **Migration `0024_item_status.sql`.** A pre-check that raises naming any item with two live graph
  runs; `uq_run_item_live`; with `trg_item_updated_at` off, ANA-35 §7.1's mapping: `done` or `failed`
  rows that their latest graph run explains → `open`, an unexplained `done` → `closed`/`done` with a
  note, an unexplained `failed` → `blocked` with a note (notes as the item's `created_by`), an item
  over a live run → `open`, the rest of the five removed values → `open`; then the auto-named
  `item_status_check` is swapped for `chk_item_status` (three values). No new table (`TABLES` 51); no
  cache migration (the schema-version bump rebuilds every mirror).
- **Search** (Decision B, MOD-159's "no versioned names in development"): a payload-schema stamp
  (`PAYLOAD_SCHEMA = 2`) beside the embedder stamp. A collection that carries this embedder's stamp and
  an older or missing payload stamp is dropped and recreated on first use and the next sync refills it;
  a newer stamp is refused, never dropped; a collection with no embedder stamp gets the embedder stamp
  only. The collection keeps its name `htui_concepts_v2`.
- **MCP:** `item_status` and `search_concepts` offer the three statuses; the prompt's upstream line
  prints the state word (`(running)`, not `(in_progress)`).
- **TUI:** theme and the kit status table keyed by `ItemState` in attention order; the kit `STOPPED`
  glyph moved from `⊘` (shared with blocked) to `■` (Decision A). The Backlog list, Body, Graph,
  requirements coverage and leave overlay show the derived mark and word instead of raw stored words;
  the status facet offers the nine states; `toggle_queued` refuses done and closed states; the
  runs-pane close-out picker offers only what the item can close as. The Body shows a dim placeholder
  for an open item until its runs arrive, never a guessed `open`.
- **Demo fixture:** RUN_4..RUN_8 give every `ItemState` an item (FEAT-1 a running rework run, TOOL-1
  an interrupted parked run, CLEAN-1 failed, agy ANA-1 done, vulkan FEAT-1 stopped). This moved the
  top-bar counts in many htui snapshots; every moved snapshot was reviewed.

## Deviations from ANA-35 (the tree moved since 2026-10-18)

MOD-125's `stopped` run status got its own display state and joined every live set; the search change
is a drop-and-rebuild on a stamp, not a `v3` rename; the Backlog's status grouping and `h` toggle do
not exist yet (MOD-119), so MOD-144 rekeyed only what exists; `create_run`'s implicit guard
(`legal_move(.., Queued)`) became an explicit check. Full table: the plan's Deltas and the blueprint's
PD1-PD18.

## Review

The configured reviewer (`rust-reviewer`, three area instances) approved with warnings: no critical or
high. All three flagged the enqueue race (fixed with `block_if_idle`, pinned by a conformance case and a
two-connection Postgres test); the others fixed in round R1 were the newer-stamp drop, the Body's
guessed `open`, the 0024 live-run row, the startable sentence (now the state word), a shared
`latest_live_graph_run`, test names and asserts. Recorded without a code change: `■` is East-Asian
ambiguous width (as `○ ● ◐` already were); two unit tests compare code with itself (the cache-vs-Pg
and conformance tests are the real guards); five snapshot families moved only for demo-data reasons.

migration refuses readably if any item has two live graph runs.
