## Milestone 1: what was built (2026-10-28 to 2026-11-03)

- **Snapshot v2** (`htui-core` `model/run.rs`). `GraphSnapshot::V` is 2, `V1` 1. New:
  - `edges` keyed by node name, `source` (`pin` / `kind_default`);
  - `SnapshotGraph.scope` and `revision`;
  - the bounds (`max_parallel_sessions` 4, `max_plan_revisions` 3, `max_child_runs` 8, `runtime_changes` `ask`),
    read from `app_setting` with code defaults (D13);
  - per node `role`, `palette`, `plan_scope`, `divide`, after `persona` and skipped at their defaults, so a
    linear phase serialises byte-for-byte as v1 and keeps its v1 digest. `split` is a derived accessor (A1).
  - The v2 `topology` hashes typed `{phases, edges}` (edges in one canonical order, predicates key-sorted);
    never through `serde_json::Value`.
- **The v1 lift.** `command::snapshot_of` reads v1 and v2 and lifts a v1 snapshot through the default-edge
  rule (`seed::default_edge_plan`, shared with `seed::default_edges`), keeping `v == 1`.
- **One graph validator** (`store/graph_rules.rs`, D9): forward edges (`next`, `if`, a forward `asks_you`)
  are acyclic, and a `changes_requested` or `fails` edge must loop back. Called by both stores'
  `replace_graph`, by the override clone and by resolve, with one sentence each.
- **Default edges kept in step** (D7, A5). `create_phase`, `update_phase` (name or position) and
  `delete_phase` re-derive a default-edged graph's edges in the same write, in both stores (PgStore after
  MOD-137's revision bump, so no new lock order). Authored edges are left alone; palette phases are outside
  the rule. **Migration `0023_default_edges_repair.sql`** repaired graphs Settings › Kinds had edited row by
  row since `0020` (D8).
- **Resolve writes v2** (T4). PgStore reads graph, phases, agents, parts, edges and personas in one
  `REPEATABLE READ, READ ONLY` transaction. A divide node is expanded and then refused; resolve refuses
  `InvalidGraph` (the validator's sentence) and `NotYetRunnable` (divide, palette, or edges other than the
  default ones: M1 still walks by position).
- **Pinned resume** (T5, D5, A6). A v2 run never reads the live graph; if its own phases and edges no
  longer hash to its digest it parks as `Resume::SnapshotTampered` with a note. A v1 run compares its lifted
  snapshot with the live graph, and a live graph M1 refuses is compared on the phases alone, as before
  MOD-138, so pre-upgrade runs on a palette or authored-edge graph are not stranded.
- **Workspace and library graphs** (T6, D12, A3, A4, A7). Kinds and items may name their project's graphs,
  a graph of a workspace holding the project, or a library graph (`graph_usable_by`, `usable_graphs`).
  `delete_workspace` refuses while a kind or item holds one of its graphs. A kind's graph is checked only
  when an edit changes it, as an item's is. The item and kind forms label shared graphs `· workspace` /
  `· library`.

## Milestone 2: the readiness walker (2026-11-05)

Maintainer answers before planning (2026-11-05):
- **Q-A:** an `if` is decided once and stored (`run_step.branch`).
- **Q-B:** `asks_you` is one prompt, the gate answer.
- **Q-C:** the recovery frontier stays position-based until M3.
- **Q-D:** the "a node named review loops" rule goes.

What was built:
- **The closed `if` set** (`htui-core` `model/predicate.rs`, D3):
  - `all_changed_paths_match` and `any_changed_path_matches` (`repo:glob`; a bare glob means the primary
    repo), `verify`, `item_kind` (the key-prefix grammar), `item_tag`, and the combinators `all`, `any`, `not`
    (nesting cap 32).
  - The validator refuses anything else as W4, at save and at resolve.
- **`run_step.branch`**: migration **`0025_run_step_branch`** (JSONB, `chk_run_step_branch` a strict, silent
  jsonpath: an object of booleans) and cache **`0008_run_step_branch`**.
  - `WriteStore::record_branch` writes it once (first write wins, fenced, only on a `done` step), with the same
    refusal sentence in both stores.
- **The walker** (`htui-orch` `walk.rs`, D1, D2):
  - `ready()` re-derives readiness from rows each pass: joins wait for every forward in-edge, and need one taken.
  - Skips are derived and propagate, and rows win.
  - Order is topological over forward edges, with `Cursor::Decide` and `Cursor::Loop` first (A6).
  - `status::cursor` is `ready()[0]`.
  - A parity oracle (about 98,500 row combinations per form, over raw v1, v2 and gapped lifts) proves that
    every lifted linear graph walks exactly as the old position scan, which is kept test-only.
  - `required_inputs` follows forward reach (D9).
- **Loops over edges** (D7, Q-D): `gate::edge_loop` replaces `review_loop` and `loop_target`.
  - Any `changes_requested`, `fails` or back `asks_you` edge loops to its named target.
  - The region is the forward paths from target to source, retired target first, source last.
  - The budget is the edge's `loop_limit`, else the target's `retry_limit`.
  - The no-progress test applies, except for `asks_you` (A5), and a spent loop ends in `RunFailure::LoopExhausted`.
  - A node reads a verdict when it has a `changes_requested` edge (`reads_verdict`).
  - The `changes_requested` note bytes are kept.
- **Decisions and asks** (D6, D8):
  - `Decide` evaluates a node's `if` edges from `BranchFacts`; it reads changed paths only when a predicate
    needs them, and records the decision. An isolator error parks resumably.
  - An `asks_you` node always stops after an ok settle; auto mode does not skip it. Approve takes the edge.
  - Reject declines only that stop (A10); a reject of a failed park takes the node's own gate path. Reject
    order is `changes_requested` loop, then `asks_you` decline, then `fails` loop, then end the run (A3).
  - Accept-artifact declines (A2). A spent back `asks_you` writes its escalation without blocking the item (A9).
- **Resolve** runs authored edges (D10). It refuses a fan-out node with an `asks_you`/`fails` edge (A7) and a back
  `asks_you` beside another `asks_you` edge (A11, `NotRunnable::MixedAsksYou`; M3 moved the refusal into the
  validator as rule W5, at save and at resolve, and removed the variant).
- **v1 resume** compares the phase-only digest (D11).
- **The queue** now says "loop exhausted" for any blocked loop escalation, not "review loop exhausted".

## Milestone 3: concurrent nodes (2026-11-07 to 2026-11-08)

Maintainer answers before planning (2026-11-07):
- **Q-1:** the recovery frontier is derived from rows (`recover::frontiers`); no column, no migration.
- **Q-2:** drain on park, cut on end. A park lets the live siblings finish and land; a node that ends the run cuts
  them, and their rows are cancelled with a note naming the node that ended it.
- **Q-3:** mixed `asks_you` edges stay refused, now at save too (validator rule W5).
- **Q-4:** the join behind a declined `if` is fixed here: a kind whose only producers were skipped is optional.

What was built:
- **The scheduler** (`htui-orch` `schedule.rs`, pure; D1, A1-A3). `run_to_rest` keeps a `FuturesUnordered` of
  boxed per-node `drive_node` futures over owned inputs and re-derives readiness each pass (`walk::ready_masked`,
  in-flight nodes masked). `plan_pass` admits a cursor only when:
  - its node has no future yet, and it is incomparable over forward edges with every node in flight (A2), so a
    chain still runs one node at a time and every linear graph walks exactly as before;
  - no in-place (`local`, `shared_serialized`) Run, Fan or Select overlaps another tree-touching future (A3);
  - no in-place node starts while another node's selection is owed (the owed landing goes first);
  - no node in flight or unfinished, and incomparable with it, produces one of its input kinds (review R1, below);
    of two nodes needing each other's kind the lower position goes first, and when every candidate waits only on
    this rule with nothing in flight, the lowest position is admitted alone, so no cycle deadlocks;
  - the weights fit `max_parallel_sessions` (Run, Create and Fan weigh their fan-out; a cap of 0 reads as 1; a
    node heavier than the cap runs alone).
  Strict park (A6): any awaiting, running or stopped rest blocks admission; resumes read `status::run_resumable`.
- **Drain and cut** (D3, A4, A5, A11). `WalkScopes` gives each walk one cut channel that every session watches
  (the run's own cancel is copied in at each read). `settle_walk` decides in a fixed order: a fenced error, the
  owed cleanup (deferred while a sibling is in flight, A4), the run cancel (I-6 writes nothing), then the cut
  writes, then the first terminal rest, error or park (A11). The cut writes move every unsettled row of a
  terminal run to `cancelled` with "step `X` attempt N cancelled: the run ended at `Y`"; they are best-effort
  (review R1). A rejection that ends the run, in process or handed back, cancels the other parked step the same
  way.
- **A park on a parked run.** `park_the_run` (engine) and its gate twin (`gate::WalkPark`) accept an
  already-parked run only when a sibling of the same walk could have parked it (`WalkScopes::shares_park`) or the
  recovery parked it itself (`open_recovery`). Narrower than blueprint §3.7, so plan D145's
  `a_stale_write_mid_sweep_writes_no_note` still raises `StaleWrite` unedited.
- **Recovery among concurrent landings** (D6, A7-A10). `recover::frontiers` replaces `recover::frontier` (removed):
  every done, unlanded winner is a member; a successor proves its predecessor landed only by a row started at or
  after the winner finished (A8; a pending retry proves it through an earlier attempt); of in-place landings
  only the last one counts (A9). `recover_run` re-lands every member in topological order, then adjudicates
  every running row (A7: the first park is kept, an end cancels the rest). `walk_resumed_from` lands every
  member, and an answer lands the other frontier members before its tail, approval or rejection (A10, widened in
  T4's repair). A rejection handed back (`Tails::HandBack`) beside a parked or interrupted step ends exactly as
  in process.
- **Resolve and the validator** (D7, D8). `ResolveError::LocalConcurrent { first, second }` refuses `local`
  isolation on two nodes that can be live together (a v1 run resuming on such a live graph compares phases, as
  under M2). Rule W5 (`mixed_asks_you_refusal` in `walk_refusal`) replaces `NotRunnable::MixedAsksYou`, divide
  expansions included.
- **Inputs** (D9, D11). `required_inputs(phase, snapshot, steps)` and `walk::input_needs`: `Required`, `Later`
  (a reachable later node makes it), `SkippedUpstream` (every producer skipped: optional, with a note), and
  `Concurrent` (an incomparable producer has not finished while the node already runs; optional, with a note).
  `last_output_kind` follows the graph's sinks.
- **The real isolator** (D5). Tests prove the per-repo admin lock serialises two worktree landings of one run and
  that a `shared_serialized` guard is released at capture. A re-land finds its merge (`merge_of`) before the
  dirty-tree refusal, so an idempotent re-land never parks on a dirty primary (review R1).
- **Cleanup.** The manual Cleanup (R-25, `Engine::cleanup_run`) also settles rows a failed cut left; a walk
  dropped with its cleanup still owed (lease expiry) warns and names that retry.

## Milestone 3 review

`rust-reviewer` over the whole M3 change set: block, on one high finding and four low; a verifier per finding
confirmed all five.
- **High, a spec gap:** a node could list an input kind made by a sibling running beside it. On the DIAMOND over
  the seeded kinds (`implement` lists `plan`), `implement` failed `MissingInput` on a first run, or read an older
  run's plan through the cross-run fallback. The maintainer chose **order by inputs** (no graph refused): the
  scheduler rule above.
- **Low, all fixed:** a terminal rest names the ender over an earlier error; best-effort cut writes and the
  Cleanup retry; `merge_of` before the dirty check; the warning on a dropped owed cleanup.
- Also fixed in R1: T4's open findings (a handed-back rejection beside an interrupted park; the `CASES` prose).

Disclosed outside the task file sets: `crates/htui-orch/tests/review_loop.rs` (`walk: None` on five `GateContext`
literals) and `htui-core` `store/mem.rs` (`MemFault::TransitionStep`, `MemFault::StepTrees`, test-support only).

Known gap, not fixed: an in-process (`Tails::Walk`) crash between a rejection's `answer_gate` write and its unpark,
while another step is parked, leaves a run `run_resumable` reads as not resumable, so resume leaves it at rest.
Nothing is lost; the run stays parked for a human.
