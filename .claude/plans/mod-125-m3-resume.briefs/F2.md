## Findings

1. **No Postgres test of the cancel's follow-up closure.** On PgStore, nothing asserts the
   `FOLLOW_UP_RUN_CANCELLED` resolution or the closed `follow_up_window` that `cancel_stopped_run` writes. The
   generic case only sees `settle_follow_up` answer `NotPending` (`crates/htui-core/src/store/conformance.rs`
   ~:4091-4103). In `crates/htui-store/tests/pg_criteria.rs`, either extend
   `a_cancel_racing_a_stop_waits_for_it_and_lands_for_the_box` or add a case. Use raw SQL to assert the resolution
   equals `FOLLOW_UP_RUN_CANCELLED` and `closed_at IS NOT NULL` for the run's windows.
2. **The workspace-delete refusal points the user at resume.** It should say a direct cancel works.
   `crates/htui-core/src/store/traits.rs`:
   - ~:3789-3790, the `workspace_has_live_run` doc: "a stopped run is resumed first, then finishes or is cancelled".
   - ~:3804-3807, the `workspace_has_stopped_run` doc: "cancelled or finished only once resumed (M3)".
   - ~:3815-3816, the **user-facing refusal**: "resume the workspace and finish or cancel them".
   - The pinned test at ~:4669-4674.

   Reword the refusal to "cancel them, or resume the workspace and let them finish". Make both docs say the same,
   and update every pin of the text (grep both stores and the htui crate for it).
3. **ANA-2 retires a move the code still allows.** ANA-2's M3 amendment (`docs/ANA-2.md` ~:730) says run
   `stopped -> failed` is retired, but `RunStatus::can_move_to` still allows `Stopped => … | Failed`
   (`crates/htui-core/src/model/run.rs` ~:92, test table ~:1736). First check whether any production path, or any
   Postgres trigger or CHECK, relies on that move. If none does and no migration is needed, remove `Failed` from the
   `Stopped` arm and its test row. Otherwise keep the move and reword the ANA-2 line to "allowed but written by
   nothing". Say which you chose.
4. **The `StepStatus::Stopped` doc misses `superseded`.** The doc (`run.rs` ~:169-172) says "otherwise cancelled
   or failed with its run". Add that `select_fanout` supersedes a stopped loser or judge.
5. **The TUI side never resumes a forced stop to `done`.** The plan's acceptance criterion "A worker walk and a TUI
   walk each resume a graceful and a forced stop to `done`" has no TUI-side forced-stop test.
   `crates/htui/src/run_worker.rs` (~:4695-4846) only resumes graceful stops. Add a forced twin that walks to
   `done`, in paused time with the fake driver, beside `a_resumed_walk_can_be_stopped_again`.

Deferred (do NOT fix): `pending_resumes` has no index. It goes into M4's migration `0031`.
