## Summary

Four new MCP tools next to `command_run`: `command_start`, `command_wait`, `command_cancel`,
`command_output_read`. A started command runs in a session-owned background task over the same
`command_run` rows (same fence, scrub and class limits). Every command row (blocking or started)
gets a scrubbed, size-capped log in a new `command_log` table. A `repo` argument on `command_run`
and `command_start` resolves the session's `extra_dirs`, which the engine now puts into
`ToolScope`. `command_run` stays the blocking form and keeps its answer shape.

## Shared decisions (every brief carries this section)

- **D1 Storage.** New table `command_log(command_run_id PK → command_run ON DELETE CASCADE, text
  TEXT NOT NULL, truncated BOOL, total_bytes BIGINT, written_at TIMESTAMPTZ)`, migration
  `0031_command_log.sql` (latest today: `0030_link_kinds`; the number may need renumbering at
  collect). A separate table, not a column: `CommandRun`, `NewCommandRun` and every
  `command_runs()` read stay unchanged and cheap. `command_run.output` stays the 64 KiB scrubbed
  tail.
- **D2 Cap.** `COMMAND_LOG_CAP = 2 MiB` of the *tail* of the merged output (32× the row tail). A cut
  log opens with `[… earlier output truncated]` (the existing `TRUNCATED` line) and starts on a line
  boundary. The store accepts at most `COMMAND_LOG_CAP + 4096` bytes (room for the marker) and
  refuses more with `Constraint`.
- **D3 Scrub, fail closed (R-ID-7, R-SEC-3).** The log is scrubbed as one text before it is stored;
  a text that cannot be masked is stored as `[log withheld: it matched credential rule <rule>]`
  (the `answer_output` precedent). A live read (T5) serves only *complete* lines and scrubs the
  slice it returns; a slice that cannot be masked is withheld the same way. NULs become U+FFFD.
- **D4 Persist order.** The runner writes the log, then `finish_command`. A waiter that sees a
  terminal status can read the log at once. A reaped or crashed row has no log (its row output says
  why).
- **D5 Store surface — two methods, mirrored through every layer `cancel_command` goes through**
  (`WriteStore`: `traits.rs`, `mem.rs` State+MemStore, `pg/write.rs`, `writer.rs`, spies
  `UsageSpy`, `SpyStore`; `WorkerStore`: `worker.rs` trait, core `MemStore`, store `PgStore` and
  `Writer`; conformance case):
  - `put_command_log(&self, log: CommandLog) -> Result<()>` — upsert by `command_run_id`; unknown row
    is `NotFound { entity: "command_run" }`; oversize is `Constraint`. Unfenced like the queue's own
    writes (the row is the fence).
  - `command_log_of_run(&self, run: RunId, id: Option<CommandRunId>) -> Result<Option<StoredCommandLog>>`
    — `None` when `id` names no row *of that run*, or (`id: None`) the run has no command row;
    `id: None` means the latest row by `queued_at`. This is the "caller's run's rows" scope: a later
    step of the same run reads an earlier step's gate log.
- **D6 Executor.** `run_shell` gains a streaming twin `run_shell_with(.., sink)`; `run_shell` is a
  wrapper over it with a no-op sink, so its tests and `command_run`'s answer shape do not move.
- **D7 Started commands.** One background task per started command, spawned with
  `htui_agent::contained::spawn`, owned by a per-session registry `Session.commands`. At most
  `START_LIMIT = 4` started rows are queued-or-running per session (`command_run`'s own
  `command_slot` is unchanged and separate). Session end (`Session.cancel`) or `command_cancel`
  stops the child and ends the row `cancelled` with a one-line reason; a lost lease ends it as
  `command_run` does today (`LEASE_LOST`).
- **D8 Wait.** `command_wait` takes an absolute RFC 3339 `deadline`, clamped to
  `MAX_WAIT = 300 s` from now; it never outlives the client. It returns when the row is terminal,
  a line matching `pattern` (Rust `regex`, per line, from `after_line`) appears, or the deadline
  passes. It ticks progress like `command_run` does.
- **D9 Approval posture (ANA-36 §7.4 rule 11) — needs the maintainer's yes.** `command_start`,
  `command_cancel` and `command_wait` are added to `ASKING_TOOLS` as the item text says ("kept in
  `ASKING_TOOLS`"); `command_output_read` is not (it runs nothing and reads a scrubbed log).
  *Recommendation:* take `command_wait` **out** of `ASKING_TOOLS` too — it runs nothing, and an
  approval prompt on every poll defeats the tool. CONFIRM decides; the default in this plan is the
  recommendation (start + cancel ask; wait + output_read are pre-approved).
- **D10 Advertised with `command_run`.** All four use `advertised: |scope, _| scope.command_queue`.
  Persona narrowing, `D16` exposure and the OQ-5 prefix denials are untouched. `COMMAND_QUEUE_TEXT`
  is **not** reworded here (MOD-151 owns the prompt digest change).
- **D11 `repo` argument.** `ToolScope.extra_dirs: Vec<PathBuf>`; a name is the directory's final
  path component. Unknown name → `refused: repo `x` is not one of: a, b`; two dirs with one name →
  `refused: repo `x` names more than one directory`. `repo` absent → `scope.cwd` as today; `cwd` stays
  relative to the chosen base and keeps the no-`..` rule.
