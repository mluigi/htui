## Findings to fix

**M1 - a person's edit to a run-written entry is not protected.** The Settings pane lets a person amend a
run-written entry (`apply_memory_edit`), but it keeps `source = run`; a later capture on the same subject
supersedes the person's text. `write_run_memory` (`pg/write.rs` ~:10632, `mem.rs` ~:9432) branches only on
`source == Person`. Runs only create entries at version 1 and only move entries to `superseded`, so a live
`source = run` entry with `version > 1` has been edited by a person: answer `RunMemoryWrite::PersonHolds`
for it too, in both stores, and document the rule on the trait (`traits.rs` ~:2700). New conformance case:
a run entry amended by a person is held, nothing written, the person's text kept.

**L2 - the Postgres write cap is not serialized.** `step_scope` takes `FOR SHARE` on step and run, so two
concurrent calls on one step could both count 2 and both insert. Take
`SELECT 1 FROM run_step WHERE id = $1 FOR NO KEY UPDATE` before `step_scope` in `write_run_memory` (do
**not** upgrade inside `capture_facts`: two transactions already holding `FOR SHARE` would deadlock). Note
the serialization in the trait doc.

**L4 - the store accepts any evidence.** Refuse, in both stores, an empty `citations` list and any citation
whose `step_id` is not a step of the scope's run, with `StoreError::Constraint(MEMORY_EVIDENCE_OUTSIDE_THE_RUN)`
(new constant `"memory_evidence_outside_the_run"` beside `MEMORY_NEEDS_A_CAPTURE_STEP`, re-exported the same
way). Refusal order: after the capture-step check, before the cap. New conformance case(s).

**L5 - no index on the new `run_id` and `item_id` columns** (0031 :34-53). `ON DELETE SET NULL` scans
`memory_entry` per deleted run/item. Add partial indexes `(run_id) WHERE run_id IS NOT NULL` and
`(item_id) WHERE item_id IS NOT NULL` to 0031, with a header line saying why (as the `step_id` index has).
Move any index pin in `tests/migrations.rs` that lists indexes.

**L6 - no test of the trigger's other half.** In `the_0031_checks_refuse_what_they_name`
(`tests/migrations.rs`) add two raw-SQL assertions: an UPDATE moving counters **and** `body` moves
`updated_at`; a no-op `SET body = body` moves it too.

**L8 - `light_model` model value loosely checked** (`prompt/settings.rs` ~:935 `light_model_of`): trim before
counting characters (an all-space model is refused) and refuse a model containing `\0`. Tests beside the
existing light-model validation tests.

**L9 - doc lines over 100 characters** added by this item: `prompt/memory.rs` (doc on `select`),
