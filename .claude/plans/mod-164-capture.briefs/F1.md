## Findings to fix

**H1 - a capture under an already-cut walk stops the run from finishing.**
`engine.rs` `end_run` (~:9495) skips `finish_run` on `EngineError::Cancelled`, but `drive_once` drives on
`session_control` (~:1141), which is the *walk's* channel when a walk scope is open. When a sibling errors,
`WalkEnd::end_at` cuts the walk (`walks.cut(run)`, `run_to_rest` ~:4202/:4236); a node still in flight that
then reaches a terminal path goes `end_run` -> `capture` -> `drive_once`, sees the cut, returns `Cancelled`,
and `finish_run` is never written. The run stays `running` with a `running` capture row.
Fix: the capture is a run-end step, not a walk sibling - drive its session on the **run's own** control, not
the walk's. In `end_run`, only a real run cancel (`(self.parts.control)(run)` signalling cancel) passes
through without `finish_run`; any other `Cancelled` settles the capture row (interrupt, note "cut by the
walk") and still finishes the run. New conformance case: a sibling error cuts the walk, then another node
fails -> the run ends `failed`, capture row settled.

**H2 - a live capture runs inside a node future while siblings keep running; a second end breaks it.**
During the (up to 10-minute) capture, the walk keeps admitting work; a sibling reaching `end_run` finds the
first capture row `Running`, calls `interrupt_step(CAPTURE_INTERRUPTED)` (meant for crash leftovers), and
finishes the run under the live capture. `end_run` also never checks the run is still live.
Fix:
- Skip capture unless the re-read run is `Running` or `AwaitingApproval`.
- The run's outcome is decided when `end_run` is entered: stop the walk's siblings (cut the walk) **before**
  the capture session starts, so nothing new is admitted while it runs.
- Record "capture in progress" for the run in the engine (e.g. in `WalkScopes`), so a second `end_run` in
  this engine neither interrupts the live row nor finishes underneath it (it waits for or leaves the run end
  to the first). Crash leftovers (no live capture in this engine) are still interrupted as now.
New conformance case with a **live** (scripted, non-skipped) capture and a sibling that ends terminally
meanwhile: one capture row, settled done, the entry written, the run finished once.

**M4 - a capture row left `pending` by a crash is never settled.** `engine/capture.rs` ~:152-162 only
interrupts a `Running` row. Settle a `Pending` capture row too (e.g. Pending -> Running -> interrupt, or a
legal cancel), then return. Test it.

**L5 - `capture_done` turns errors into strings** (`engine/capture.rs` ~:256-270), bypassing
`passes_through`. Return `EngineError` and sort it with `passes_through` in `capture()`.

**L6 - a failed run read in `end_run` blocks the finish** (`engine.rs` ~:9483, `self.run(run).await?`).
Log the read failure and fall through to `finish_run`.

**M3 - the evidence check can be met by quoting the block's fixed labels.** `capture.rs` `check_citation`

quotes against those only. Parser test: a quote lying only in a label line is dropped as uncited.

**L7 - `OverCap` counts answer positions, not kept entries** (`capture.rs` ~:599). Count kept entries: an
