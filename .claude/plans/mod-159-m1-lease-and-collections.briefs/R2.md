## Findings to fix

1. **(medium, store reviewer) Ctrl+R and the TUI index job share one owner token.** Ctrl+R gets `Taken`, the job's
   next beat gets `Ours` on the same row and starts a reconcile, Ctrl+R finishes and lets go, the job's next guard
   answers false and abandons a legitimate pass. Fix: Ctrl+R first tries `renew_indexer_lease(collection,
   runtime_owner, ttl)`; true → the job (or a previous press) holds it: sync under the runtime owner with the renewing
   guard, keep the lease. Otherwise take with a **fresh per-press owner** (`Uuid::now_v7()`): `Taken` → sync with a
   guard renewing under that owner, then `release_indexer_lease(collection, press_owner)` (replaces the zero-TTL
   renew); `Ours` cannot happen for a fresh owner; `Held` → `HeldBy` as today. An aborted press (superseded or quit)
   leaves its press lease to lapse within the TTL; that is accepted. Update the tests that pin the old behaviour and
   add one: the job holds the collection (runtime owner) → Ctrl+R syncs and the job's lease is still live and
   renewable by the runtime owner afterwards.

2. **(medium) `combine` hides a workspace failure** (`concepts.rs` ~1141-1166). The empty `htui_global` always
   answers, so a failing workspace collection (e.g. embedder mismatch) becomes exit 0 with the reason dropped. Fix:
   only workspace parts (slug present) count as "answered" when choosing between hits and the failure; when some
   workspaces answered and others failed, keep `unavailable` and also carry the first failure's text into the stderr
   note (JSON: keep `unavailable`; add nothing else unless it falls out naturally). Tests: global hits-empty plus one
   failed workspace → the failure (its exit code, as before the change); one answered and one failed workspace → hits
   plus `unavailable` naming the failed one.

3. **(medium) A long reconcile stops renewal of every other held lease** (`index_beat` ~680-703). While one
   collection syncs (minutes on a first build; TTL 120 s), the other held collections miss their renewal and lapse.
   Fix: while `reconcile` runs, keep renewing the other held leases every `times.refresh` (race the pinned reconcile
   future against a renew ticker with `tokio::select!`); a renewal that answers false drops that collection from
   `held` after the sync. Test with paused time: a counting `JobIndex` whose sync sleeps longer than the TTL; assert
   the other collection's lease stays live (a second owner's take answers `Held`).

4. **(medium) The TUI reads the interactive keyring every beat** (`concepts.rs` ~630, `concepts_worker.rs` ~337-355).
   Each beat resolves the full settings including the key (`resolve_key` on `KeySource::Interactive`), which may
   prompt a locked Secret Service every 40 s and, on failure, warns every beat and drops every cached connection.
   Fix: each beat resolves only the URL (enough for "no URL: take nothing"; take/renew leases by URL presence);
   resolve the key only when a held collection is due, right before opening it. A key failure is logged once until it
   changes (as `no_url_said`), and drops only the index job's connections, not the search's. Test: a source whose key
   resolution counts calls → beats with nothing due resolve the key zero times.

5. **(medium) `SearchIn::Everywhere` fails on the first failing collection** (`concepts_worker.rs` ~916-981). One stale
   or mismatched `htui_ws_*` collection fails every MCP `search_concepts`. Fix: log and skip a failing collection;
   answer an error only when every collection that exists failed. Apply the same rule to `SearchIn::Workspaces` in the
   TUI path. Test over `MemIndex`: one collection fails, the others still answer.

6. **(low) Shutdown order** (`store_worker.rs` ~3904): call `concepts.shutdown()` (aborts Ctrl+R tasks) before
   `concepts.stop_index_job().await`.

7. **(low) Release bound.** `IndexJob::stop` takes its bound as a parameter (`RELEASE_WAIT` 5 s): the worker passes
   5 s, the TUI about 1 s (the store worker's whole `SHUTDOWN` window is 5 s, `crates/htui/src/lib.rs:65`).

8. **(low) Offline → online in `publish`** (`concepts_worker.rs` ~1530-1540): on a `None` publish the stopping handle
   is detached, so a job started within the old release's window gets `after: None` and the old owner-wide release
   can free the new job's leases. Keep the last stopping handle in `JobSlot` and hand it to the next spawn even across
   a `None` publish. Fix the comment that claims this cannot happen.

9. **(low) Abandoned Ctrl+R reads as success** (overlay ~487-489, `concepts_worker.rs` ~1695): when the report is

11. **(low) `IndexJob::stop` swallows a panic** (~866): log `tracing::error!` when the joined task panicked.
