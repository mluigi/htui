## Findings to fix

1. **(medium) No test of concurrent takes.** All 8 cases are sequential; the one-winner invariant and the
   `TAKE_ATTEMPTS` retry loop in `pg/indexer_lease.rs` never run under contention. Add a PgStore-only test in
   `pg_conformance.rs` (it is not a conformance case, so it does not move the case count): over several rounds,
   `futures::future::join_all` 8 takes by distinct owners (and distinct or same box) on (a) a collection with no row
   and (b) a lapsed one (taken first with a zero TTL by another owner). Assert exactly one `Taken`, seven `Held`
   whose lease names the winner's box and is live, and that only the winner's `renew_indexer_lease` answers true.

2. **(low) `Ours` for the owner's own lapsed lease is unpinned and the docs contradict it.** Both stores answer `Ours`
   when `owner` held the row last, even if it lapsed; a renew of one's own lapsed, untaken lease answers true. Reword
   the docs on `LeaseTake::Taken` ("free, released, or lapsed under another owner") and `LeaseTake::Ours` ("`owner`
   holds it, or held it last and no one has taken it since, even if it lapsed"), and the trait method docs to match.
   Add case `an_indexer_lease_its_owner_let_lapse_is_ours_again`: take with zero TTL → renew with a real TTL is true
   and the lease reads live; renew with zero TTL again → take → `Ours`.

3. **(low) Single-collection release.** Add to the trait
   `fn release_indexer_lease(&self, collection: &IndexedCollection, owner: Uuid) -> impl Future<Output = Result<bool>> + Send`
   — clears the owner and sets the expiry to now only where `collection` matches and `lease_owner = owner`; keeps
   `lease_box_id` (as the release-all does); answers whether a row changed. Pg:
   `UPDATE indexer_lease SET lease_owner = NULL, lease_expires_at = clock_timestamp() WHERE collection = $1 AND lease_owner = $2`.
   MemStore the same; Backend forwards (Offline → `Unreachable`, as the other verbs; extend its unit test). Add case
   `releasing_one_indexer_lease_leaves_the_owners_others`: owner A holds two collections, B holds a third; A releases
   one → true, that one is takeable by B (`Taken`), A's other one is still live and A's renew of it is true; A's renew
   of the released one is false; releasing again → false; B's release of A's live one → false and changes nothing.
   Regenerate `.sqlx` for the new query (recipe below). Count pins move 8 → 10 with findings 2 and 3.

4. **(low) Ask the guard right before the delete.** In `vector_sync.rs` the guard renews before `confirm`'s fresh
   reads. Reorder: `confirm` first, then ask the guard only when the confirmed batch is non-empty, then delete.
   Adjust the tests that count guard asks (e.g. `the_guard_is_asked_once_per_project_with_something_to_delete`,
   `an_item_created_after_the_listing_keeps_its_points` expects 0 asks when the only orphan was confirmed alive).

5. **(low) Confirm by re-listing, not one read per orphan.** Replace the per-id `read.item` / `read.requirement`
   confirmation with one re-listing per kind for the project (`read.items` over a one-project scope with
   `ItemFilter::default()`, `read.requirements(project, &RequirementFilter::default())` — check the exact signatures),
   collect ids into a `HashSet`, keep orphans present in it. Check that the listings carry no hidden filter (closed /
   withdrawn rows must still count as present if the first listing would have indexed them — mirror what the first
   listing used).

6. **(low) Test the moved-item branch.** Add `an_item_moved_to_another_project_loses_its_points`: plant a point for
   a real item of one project under another project's id (as `plant_ghost_item` does but with the real item id),
   sync the second project, assert that point is deleted.
