## Medium

**F1 — The refusal names the level that chose the target** (maintainer decision 2026-11-15: keep the
missing-tags precedent of block plus note, and name the level).
- `EngineError::TargetRefused` (`crates/htui-orch/src/command.rs`) gains `source: TargetSource`.
- Its `Display`, which is also the note `refuse_target` writes, becomes
  `item {item}: {refusal}; chosen by {level}`. The level phrases are:
  - `the item`
  - `its workflow`
  - `its project`
  - `its workspace`
  - `the Settings default`
  - `default`, which needs no phrase and cannot refuse in practice (it is the local target). If it
    ever does, use `the built-in default`.
- Put the phrase on `TargetSource` as `pub fn chosen_by(self) -> &'static str`
  (`crates/htui-core/src/model/target.rs`), with a test pinning every value.
- Update the Display test in `command.rs` and the engine refusal tests so they assert the full note text.

**F2 — Pg race tests for `create_run`'s `FOR SHARE` target read.** In
`crates/htui-store/tests/it/pg_criteria.rs`, mirror `a_level_set_behind_a_retire_is_refused` (about
`:15402`) with two tests:
- `a_create_run_behind_a_retire_is_refused`. A second connection runs `BEGIN`, then
  `SELECT … FROM target WHERE id = $1 FOR UPDATE`, then `UPDATE target SET retired_at = now()`. Spawn a
  `create_run` with `target: Some(..)`, assert it is still pending after about 300 ms, and commit. It
  answers exactly `Constraint(target_retired(name))`, and no run is written.
- `a_create_run_behind_a_delete_is_refused`: the same shape with `DELETE FROM target`. It answers
  `Constraint(references_no_row("run.target_id", id, "target"))`, and no run is written.

## Low

- **L1 — Docs.**
  - `WriteStore::create_run`'s `# Errors` (`crates/htui-core/src/store/traits.rs`, about `:1564`) and
    `PgStore::create_run`'s doc (`crates/htui-store/src/pg/write.rs`) gain: "MOD-130 M2 P8: a
    `new.target` naming no row is `Constraint(references_no_row("run.target_id", ..))`, a retired one
    `Constraint(target_retired)`, checked after `repo_scope` and before the batch."
  - The summary paragraph of `Engine::enqueue` (`crates/htui-orch/src/engine.rs`, about `:1369`) names
    the target step: tags → resolve the graph → resolve and refuse the target → create.
- **L2 — `Retired` is a soft refusal.** A retired target can only come from a race: a stale engine `app`
  map, or a retire that landed between the reads, because retire refuses a target any level names. For
  `TargetRefusal::Retired`, `enqueue_with` returns `EngineError::TargetRefused` **without**
  `block_if_idle`, so it writes no note and does not block. The next tick re-reads the cascade. Every
  other refusal still blocks. Document this on `refuse_target`. Add an engine test showing a `Retired`
  refusal leaves the item `open` with no note: drive it with a stale `app` map naming a target that was
  then retired.
- **L3 — A scope-row item started with the wrong workspace is refused for the workspace, not the
  target.**
  - In `enqueue_with`, after reading the project: if `project.owner_workspace_id` is `Some(own)` and
    `workspace` is `Some(asked)` with `asked != own`, return the same refusal `create_run` gives. That is
    `StoreError::Constraint(scope_row_run_workspace(&project.slug, asked))`, using the existing helper,
    or `run_workspace_for`'s error.
  - Do this before resolving the target. Nothing is written.
  - Test it.
- **L4 — Cache round trip of a run's target.** Add one `cache::` test in
  `crates/htui-store/tests/it/cache.rs`:
  1. On Pg, `create_run` with `Some(ResolvedTarget { target: LOCAL_TARGET_ID, source: Project })`.
  2. Refresh the mirror.
  3. Assert the cache's `run(id)` has the same `target_id` and `target_source` as the Pg row.
- **L5 — Small consistency fixes.**
  - `MemStore::delete_target`'s `u64::try_from(runs).unwrap_or(u64::MAX)` should match Pg's
    `unwrap_or_default()`, or the reverse: pick one and make both stores use it.
  - Both `target_binding` bodies (`crates/htui-core/src/store/worker.rs`,
    `crates/htui-store/src/worker.rs:~546`) map only `NotFound { entity: "target", .. }` to `None`.
    Every other error propagates.
  - Rename the engine's private method `resolve_target` (`engine.rs:~1648`) to `cascade_target`, so it
    no longer shadows `htui_core::model::resolve_target`.
