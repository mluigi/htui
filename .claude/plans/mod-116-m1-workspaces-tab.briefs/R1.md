## Medium

- **F1 — `w` lands on the first workspace, not the open one, after a restart into a remembered workspace that is
  not first by name.** `register_all` registers `WorkspacesTab` first, so `register_tab` → `activate_tab`
  (`app/state.rs:903-911`) sends the tab's `Workspaces` request before `App::start` sends the shell's; the tab's
  `on_reply` (`ui/tabs/workspaces/mod.rs:595-613`) runs with an empty scope, its landing rule falls through to
  `first()`, and `on_scope_change` (a no-op) keeps that cursor, which the "keep by id" branch then keeps forever.
  Fix: a cursor the user never moved is re-landed on the open workspace's row whenever the scope changes (track
  "placed by fallback" vs "moved by the user"); no cursor placement and no overview read while `ctx.scope` is
  empty. Test (integration, `register_all` harness): `ui.last_workspace` = Platform (not first by name), start,
  press `w`: the selected row is Platform's group (`▌▾ Platform`) and the detail is titled Platform. This also
  replaces the deleted switcher pin `the_switcher_opens_on_the_workspace_the_shell_is_already_inside`.
- **F2 — the overview is not re-read on activation.** Plan D7: reads happen on "activation, cursor onto another
  workspace, a change in that workspace's counts". `read_if_due` (`mod.rs:~298`) returns early while the held
  overview's counts row is unchanged, and `on_activate` only calls `read_if_due`, so item counts, goals,
  description and repos edited elsewhere stay stale. Fix: `on_activate` forces a re-read; a `Workspaces` reply
  whose project ids for the held workspace differ from the overview's projects also forces one; a project row
  whose project is missing from the held overview shows the reading message, not a blank pane (`mod.rs:~421`).
  Tests: activate → leave → change (e.g. a new item through the store) → `w` → the overview shows the new count;
  a project added after the read shows the reading message, then its overview.
- **F3 — a refused overview is never retried while the counts stay the same** (both reviewers). `held` matches
  `Held::Refused` too (`mod.rs:297-298`), so `on_refresh` never asks again, contradicting `REFUSED_NEXT` ("read
  again once the database answers"). Fix: a refused overview is not "held"; `on_refresh` retries it (its refusal
  stays absorbed). Test: refuse once with counts unchanged, then answer: the next refresh asks again and shows it.
- **F4 — startup overwrites a `ui-state.toml` that failed to load.** `lib.rs:233,301` applies defaults with a
  notice and promises the file is left alone until the next change (`Loaded::fallback`, `state_file.rs:599-606`;
  test `an_invalid_file_gives_the_defaults_and_the_reason_and_is_left_alone`, `state_file.rs:1184`). The startup
  `SetScope` now calls `save_ui_state()` (`update.rs:441-446`) and rewrites it within a second. Fix: the startup
  scope (the first `Workspaces` reply opening the remembered or first workspace) sets `last_workspace` in memory
  without saving; only a person's scope change (`o`, an activity jump, Hierarchy) saves. Test: a broken file +
  startup leaves the file's bytes unchanged; an `o` afterwards saves.
