# Plan: MOD-152 — Async command queue and stored command logs

**Source**: `HANDOFF.md` item MOD-152; design input `docs/ANA-36.md` §5 #18/#19/#22, §6.2, §6.3, §7.3, §7.4.
**Routed**: plan path by maintainer override (criteria C2 and C4 fired; PRD threshold).
**Complexity**: Large — five tasks in one serial lane, ~35 files. **Branch**: `hr/MOD-152` (sandbox: never push).

## Summary

Four new MCP tools next to `command_run`: `command_start`, `command_wait`, `command_cancel`,
`command_output_read`. A started command runs in a session-owned background task over the same
`command_run` rows (same fence, scrub and class limits). Every command row (blocking or started)
gets a scrubbed, size-capped log in a new `command_log` table. A `repo` argument on `command_run`
and `command_start` resolves the session's `extra_dirs`, which the engine now puts into
`ToolScope`. `command_run` stays the blocking form and keeps its answer shape.

## Shared decisions (every brief carries this section)

- **D1 Storage.** New table `command_log(command_run_id PK → command_run ON DELETE CASCADE, text
  TEXT NOT NULL, truncated BOOL, total_bytes BIGINT, written_at TIMESTAMPTZ)`, migration
  `0031_command_log.sql` (latest today: `0030_link_kinds`; the number may need renumbering at
  collect). A separate table, not a column: `CommandRun`, `NewCommandRun` and every
  `command_runs()` read stay unchanged and cheap. `command_run.output` stays the 64 KiB scrubbed
  tail.
- **D2 Cap.** `COMMAND_LOG_CAP = 2 MiB` of the *tail* of the merged output (32× the row tail). A cut
  log opens with `[… earlier output truncated]` (the existing `TRUNCATED` line) and starts on a line
  boundary. The store accepts at most `COMMAND_LOG_CAP + 4096` bytes (room for the marker) and
  refuses more with `Constraint`.
- **D3 Scrub, fail closed (R-ID-7, R-SEC-3).** The log is scrubbed as one text before it is stored;
  a text that cannot be masked is stored as `[log withheld: it matched credential rule <rule>]`
  (the `answer_output` precedent). A live read (T5) serves only *complete* lines and scrubs the
  slice it returns; a slice that cannot be masked is withheld the same way. NULs become U+FFFD.
- **D4 Persist order.** The runner writes the log, then `finish_command`. A waiter that sees a
  terminal status can read the log at once. A reaped or crashed row has no log (its row output says
  why).
- **D5 Store surface — two methods, mirrored through every layer `cancel_command` goes through**
  (`WriteStore`: `traits.rs`, `mem.rs` State+MemStore, `pg/write.rs`, `writer.rs`, spies
  `UsageSpy`, `SpyStore`; `WorkerStore`: `worker.rs` trait, core `MemStore`, store `PgStore` and
  `Writer`; conformance case):
  - `put_command_log(&self, log: CommandLog) -> Result<()>` — upsert by `command_run_id`; unknown row
    is `NotFound { entity: "command_run" }`; oversize is `Constraint`. Unfenced like the queue's own
    writes (the row is the fence).
  - `command_log_of_run(&self, run: RunId, id: Option<CommandRunId>) -> Result<Option<StoredCommandLog>>`
    — `None` when `id` names no row *of that run*, or (`id: None`) the run has no command row;
    `id: None` means the latest row by `queued_at`. This is the "caller's run's rows" scope: a later
    step of the same run reads an earlier step's gate log.
- **D6 Executor.** `run_shell` gains a streaming twin `run_shell_with(.., sink)`; `run_shell` is a
  wrapper over it with a no-op sink, so its tests and `command_run`'s answer shape do not move.
- **D7 Started commands.** One background task per started command, spawned with
  `htui_agent::contained::spawn`, owned by a per-session registry `Session.commands`. At most
  `START_LIMIT = 4` started rows are queued-or-running per session (`command_run`'s own
  `command_slot` is unchanged and separate). Session end (`Session.cancel`) or `command_cancel`
  stops the child and ends the row `cancelled` with a one-line reason; a lost lease ends it as
  `command_run` does today (`LEASE_LOST`).
- **D8 Wait.** `command_wait` takes an absolute RFC 3339 `deadline`, clamped to
  `MAX_WAIT = 300 s` from now; it never outlives the client. It returns when the row is terminal,
  a line matching `pattern` (Rust `regex`, per line, from `after_line`) appears, or the deadline
  passes. It ticks progress like `command_run` does.
- **D9 Approval posture (ANA-36 §7.4 rule 11) — needs the maintainer's yes.** `command_start`,
  `command_cancel` and `command_wait` are added to `ASKING_TOOLS` as the item text says ("kept in
  `ASKING_TOOLS`"); `command_output_read` is not (it runs nothing and reads a scrubbed log).
  *Recommendation:* take `command_wait` **out** of `ASKING_TOOLS` too — it runs nothing, and an
  approval prompt on every poll defeats the tool. CONFIRM decides; the default in this plan is the
  recommendation (start + cancel ask; wait + output_read are pre-approved).
- **D10 Advertised with `command_run`.** All four use `advertised: |scope, _| scope.command_queue`.
  Persona narrowing, `D16` exposure and the OQ-5 prefix denials are untouched. `COMMAND_QUEUE_TEXT`
  is **not** reworded here (MOD-151 owns the prompt digest change).
- **D11 `repo` argument.** `ToolScope.extra_dirs: Vec<PathBuf>`; a name is the directory's final
  path component. Unknown name → `refused: repo `x` is not one of: a, b`; two dirs with one name →
  `refused: repo `x` names more than one directory`. `repo` absent → `scope.cwd` as today; `cwd` stays
  relative to the chosen base and keeps the no-`..` rule.

**Files owned (CREATE/UPDATE).**
`crates/htui-store/migrations/0031_command_log.sql` (C);
`crates/htui-core/src/model/run.rs`, `crates/htui-core/src/model/mod.rs` (re-exports);
`crates/htui-core/src/store/{traits.rs, worker.rs, mem.rs, conformance.rs}`;
`crates/htui-store/src/{pg/write.rs, writer.rs, worker.rs}`; the `.sqlx` offline entries it adds;
`crates/htui-agent/src/conformance.rs` (`UsageSpy`), `crates/htui-agent/tests/recorder.rs` (`SpyStore`);
the migration-count pins `crates/htui-store/tests/{connect.rs, migrations.rs}` and any `TABLES` list
or `connection__confirm` snapshot the full `insta` run reports (memory: a new migration moves ~7
pins plus `TABLES`).

**Types and signatures.**
```rust
pub const COMMAND_LOG_CAP: usize = 2 * 1024 * 1024;
pub const COMMAND_LOG_STORE_MAX: usize = COMMAND_LOG_CAP + 4096;
pub struct CommandLog { pub command_run_id: CommandRunId, pub text: String, pub truncated: bool,
                        pub total_bytes: u64, pub written_at: DateTime<Utc> }
pub struct StoredCommandLog { pub row: CommandRun, pub log: Option<CommandLog> }
// WriteStore and WorkerStore, same shape:
async fn put_command_log(&self, log: CommandLog) -> Result<()>;
async fn command_log_of_run(&self, run: RunId, id: Option<CommandRunId>)
    -> Result<Option<StoredCommandLog>>;
```
SQL: the `CREATE TABLE` of D1, `ON DELETE CASCADE`; the run join is `command_run → run_step.run_id`.
Forward-only (R-STO-5). A fresh query string is a new `.sqlx` entry: prepare against a migrated
scratch DB (`docs/hr-sandbox.md` variant; the compose database is empty).

**Tests (first).** Conformance cases `put_command_log_*` and `command_log_of_run_*` (upsert replaces;
unknown row `NotFound`; oversize `Constraint`; `id: None` = latest by `queued_at`; a row of another
run answers `None`; delete of the step cascades), run for MemStore and Postgres; one `UsageSpy`/`SpyStore`
delegation compile check.

**Check.** `cargo test -p htui-core --features test-support -- --test-threads=1`;
`cargo test -p htui-store --features test-support -- --test-threads=1` (sandbox Postgres,
`HTUI_TEST_DATABASE_URL` is set); `cargo test -p htui-agent --features test-support --no-run`.

### T2 — Executor: streaming sink

**Files owned.** `crates/htui-orch/src/verify.rs` only.

**Signatures.**
```rust
pub async fn run_shell_with(command: &str, cwd: &Path, budget: Duration,
    stop: impl Future<Output = ()> + Send, sink: &(dyn Fn(&[u8]) + Send + Sync)) -> ShellRun;
pub async fn run_shell(command, cwd, budget, stop) -> ShellRun { run_shell_with(.., &|_| {}).await }
```

### T4 — Runner refactor, log capture, `command_output_read`, `repo` (foundation)

**Files owned.** `crates/htui-mcp/src/tools/{command.rs, command_log.rs (C), mod.rs}`,
`crates/htui-mcp/Cargo.toml` (`regex = { workspace = true }`), `crates/htui-mcp/tests/tools_command.rs`,
`crates/htui-mcp/tests/tools_command_log.rs` (C); `tools/box_profile.rs` test `tools_list_per_scope_shape`
(pinned names); `crates/htui-mcp/src/host.rs` `the_lease_names_the_advertised_tools`.

**Changes.**
- `command.rs`: split `call` into `check(args, scope) -> Checked` (class, command, directory incl. D11
  `repo`, timeout, scrubbed command) and `execute(ctx_parts, Checked, external_stop) -> Finished`
  (lease read, enqueue, admit, beat, `run_shell_with` into a `LogBuffer`, scrub, persist log (D4),
  finish). `command_run` = `check` + `execute` with `external_stop = pending()`; its answer and the
  `BUSY` refusal are byte-identical (existing `tools_command.rs` pins). `CommandArgs` gains
  `repo: Option<String>`.
- `command_log.rs`: `LogBuffer { push(&[u8]), complete_lines(), into_stored(scrubber) -> CommandLog }`
  (tail-capped at `COMMAND_LOG_CAP`, counts `total_bytes`, line-boundary cut, D2/D3), the slice reader,
  and the tool:
```rust
struct OutputReadArgs { command_run_id: Option<CommandRunId>, tail_lines: Option<u32>,
    from_line: Option<u32>, to_line: Option<u32>, pattern: Option<String>,
    context: Option<u32>, max_bytes: Option<u32> }   // deny_unknown_fields
```
  Exactly one mode: `pattern` (regex, `context` default 2 max 20), `from_line`+`to_line`, or
  `tail_lines` (default 200). `max_bytes` default 16 KiB, max 64 KiB. Answer
  `{command_run_id, status, exit_code, total_lines, log_truncated, text, first_line, last_line, capped}`;
  reads through `command_log_of_run(scope.run_id, id)`; no log → `not found: command log` (a running
  row's live read is T5). A bad regex is `refused: pattern: <regex error>`.
- `mod.rs`: `ALL` grows to include `command_log::DEF` (order is a pin); `dispatch` arm.

**Tests (first).** `LogBuffer` cap/marker/line-boundary/NUL/fail-closed (unit); `command_run` still
answers as before and now leaves a log the run can read; `command_output_read` tail, range, regex with
context, byte cap, other-run row refused (`None`), a withheld log; `repo` resolves an extra dir, rejects
unknown/ambiguous, keeps the no-`..` rule.

**Check.** `cargo test -p htui-mcp --features test-support -- --test-threads=1`.

### T5 — `command_start` / `command_wait` / `command_cancel`, registry, docs

**Files owned.** `crates/htui-mcp/src/tools/{command_async.rs (C), command.rs, mod.rs}`,
`crates/htui-mcp/src/host.rs` (`Session.commands`, session-end wiring),
`crates/htui-mcp/tests/tools_command_async.rs (C)`, `docs/htui-mcp.md`.

**Changes.**
- `Session.commands: LiveCommands` — `Mutex<HashMap<CommandRunId, Arc<Live>>>`;
  `Live { log: Mutex<LogBuffer>, changed: tokio::sync::Notify, state: watch::Sender<Phase>, cancel: CancellationToken }`.
  `host.rs` cancels every live entry when the session's token fires (D7).
- `command_start`: `CommandArgs` + `repo` (shared with `command_run`); `check`, `START_LIMIT` refusal
  (`refused: 4 commands are already queued or running in this session`), lease read before enqueue,
  enqueue, register, spawn the task that runs `execute(.., external_stop)` where `external_stop`
  resolves on `Live.cancel` or `Session.cancel`. Answers `{command_run_id, status: "queued"}` at once.
- `command_wait` (D8): `{command_run_id, deadline, pattern?, after_line?}` →
  `{status, exit_code, matched, line_no, line, tail, next_line, total_lines, deadline_reached}`.
  Live rows read the registry; ended rows read the stored log (`command_log_of_run`).
- `command_cancel`: `{command_run_id}`; a live row of this session is cancelled and its answer is the
  settled status; any other row (earlier session, other run) is `not found: command_run <id>`.
- `command_output_read` (T4) consults the registry first, so it reads a running command's complete
  lines.
- Docs: `docs/htui-mcp.md` — the four tools, `repo`, the 2 MiB cap and scrub rule, lifecycle on
  session end/lease loss/cancel; replace the "raise the client timeout" advice with `command_start`.

**Tests (first).** Paused-time unit tests with no child: registry limit, wait deadline clamp, pattern
match from `after_line`, cancel of a queued row, session end ends the row. Real-`sh` e2e (real time,
separate file): start → wait for a pattern → output_read → wait done; `command_cancel` kills a
`sleep`; session end kills the child and cancels the row; a lost lease stops the child; a secret in the
log is withheld; `command_run` and `command_start` share one class limit.

**Check.** `cargo test -p htui-mcp --features test-support -- --test-threads=1`;
`cargo test -p htui --features test-support --test mcp_stdio -- --test-threads=1`.
