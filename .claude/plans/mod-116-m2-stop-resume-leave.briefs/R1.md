## Medium

- **F1 — a batch stop that fails partway hides the stops it already wrote.** `workspaces.rs:139-147` loops
  `stop_report::write_stop(...).await?`: target k failing returns `Failed` with targets 0..k-1 written; the leave
  dialog (`leave.rs:543-553`) shows `Could not stop: …` and offers `S` again, whose retry (targets from the stale
  `top_bar.workspace_runs`, `decided_on: None`) gets `Changed` for the written ones and calls them "changed
  meanwhile". Fix: a failing target becomes an outcome (e.g. `StopWrite::Failed(String)`) and the loop goes on, so
  the reply reports every target; the dialog waits for the written ones and names the failed ones ("could not
  stop Platform: …"); the tab (one target) tells the failure as today. A wholly offline request is still refused
  before any write. Tests: a batch where the second target fails (e.g. a deleted workspace) writes the first and
  reports both; the dialog waits for the written one and names the failed one.
- **F2 — offline, the leave dialog lists other workspaces from stale counts and offers `S`.** `other_rows`
  (`leave.rs:~318`) and `offers_stop` (`:~437`) ignore `ctx.top_bar.offline()`, unlike the header and the tab (M1
  R1 F6). Fix: offline, no per-workspace rows for other workspaces (at most the folded "work may be running in
  other workspaces" line) and no `S`. Test: counts known, go offline: no Platform row, no `S` hint; back online:
  both return.
- **F3 — a `Changed` target is not waited for.** The dialog always sends `decided_on: None`, so `Changed` means a
  stop row now exists (someone else stopped it in the last second). Fix (`leave.rs:~520-542`): keep `Changed`
  targets in `waited` (the "changed meanwhile" note may stay). Test: a target stopped by another writer between
  the counts read and `S` is waited for.

## Low

- **F4 — the CLI now reads `run_steps` it never prints** (`stop_report.rs:~298`, `report` → `live_steps` per
  running run), adding a failure mode to `htui stop`. Fix: `report` skips `live_steps` when the caller wants no
  steps (e.g. names `Option`, or a flag); the CLI asks for none. Pin with a test that the CLI path does not read
  steps (a store spy, or a step-read failure that the CLI no longer sees).
- **F5 — `the_cli_report_text_is_the_shared_display` (`stop_cmd.rs:~1477`) cannot fail** (equal by construction).
  Drop it, or keep it with a doc saying it is not the parity evidence (`report_stopping.snap` and the untouched
  tests are).
- **F6 — the tab drops a pending `s`/`r` silently when the overview comes back gone**
  (`ui/tabs/workspaces/mod.rs:~1068`). Fix: tell "<name> no longer exists" (the one-answer box). Test.
- **F7 — the leave dialog's `Writing` stage has no bound, and its 20-refresh bound pauses under `?`**
  (`update.rs:~415`: overlays below the top are not ticked). Fix: bound `Writing` like `Settling` (count it into
  the same 20) and measure the settle bound in wall time (the stage records when it began; `refresh` compares
  against `STOP_WAIT`) so a help overlay on top does not stretch it. Test with the harness clock the leave tests
  use.
- **F8 — offline, the settling dialog's own counts refusal hits the status line every second**
  (`App::absorbed`: `Origin::Overlay(_) => false`). Fix: absorb a `workspace_run_counts` refusal from the leave
  dialog's origin (or let the dialog say it in its box). Test.
