## M1 — document resolution leaks existence outside reach (store + MCP)

Today `propose_document_link` resolves owner + kind + version, **then** checks reach
(`crates/htui-store/src/pg/write.rs` `propose_document_link_in` ~:522, `crates/htui-core/src/store/mem.rs`
~:9426). An agent can probe an unreachable project: `not found: document …` vs `out of scope: …`
tells whether a slug, a kind or a version exists. The item path answers every such case with one
sentence (`out of scope: … is not an item of this project or its workspaces`, MOD-147 D3).

New order, the same on both stores (amends plan D4):

- **Propose:**
  1. Step scope / fence.
  2. Own item.
  3. **Owner:** resolve it to its project (an item key first, then a project slug). If the owner
     **does not resolve**, or its project is **outside reach**, refuse with
     `Constraint(document_outside_reach(&label))`. The two cases give the same sentence.
  4. **Kind and version:** resolve them within that owner. If either is missing →
     `NotFound { entity: "document", id: label }`. That answer is safe now, since the owner is in
     reach.
  5. Advisory lock (Pg), then the pin check, then the upsert, as today.
- **Withdraw:**
  1. Step scope / fence.
  2. Own item.
  3. **Owner:** resolve it to its project. If it does not resolve →
     `Constraint(document_outside_reach(&label))`. No reach check here, as in `withdraw_link`.
  4. **Live link:** find it from the item, of that link kind, to **any version** of (owner, doc kind).
     Do **not** require the document version to exist. If there is no live link, or the named
     version is not the pinned one → `NotFound { entity: "item_artifact_link", id: label }`. That
     restores the plan's D4 wording: withdrawing a version that does not exist no longer reads
     NotFound `document`.
  5. The not-ours check, then the tombstone, as today.
- **Docs and tests:** update the `WriteStore`/`WorkerStore` doc comments of both methods. Update the
  conformance cases `document_link_refusals` and `document_link_withdraw_tombstones_and_revives` to
  the new answers, and add the case of an unknown project slug, which now reads
  `document_outside_reach`.
- **MCP** (`crates/htui-mcp/src/tools/link.rs` ~:341): `document_outside_reach` already maps to
  `out of scope: document {label} is outside this project and its workspaces`. Make sure an unknown
  owner reaches that same line, and add an MCP test: an unknown slug and an existing-but-unreachable
  slug give byte-identical replies.
