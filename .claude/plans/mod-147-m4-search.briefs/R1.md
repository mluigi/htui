## M1 — the overlay treats "all projects" and a cycled project as one search in a one-member workspace
`crates/htui/src/ui/overlay/concepts_search.rs`: `enter` (~:282), `changed` (~:235) and `on_reply` (~:454) decide
"search again?" and "is this reply mine?" by comparing `sent: Option<SearchQuery>` with `current()`. But the request
also carries `scope_row_of` (D8/D9), which `SearchQuery` does not hold. In a workspace whose only member is `A`, "all"
gives `projects == [A]` with `scope_row_of: Some(ws)`, and `Ctrl+P` to `A` gives `[A]` with `None`. The queries are
equal, so after `Ctrl+P`, Enter opens a stale hit (a `WS` item or an owner document) instead of searching, and a late
reply to the "all" search is accepted after the cycle.
- Fix: track the sent request's `scope_row_of` beside `sent` (or store the pair), and compare both in
  `changed`/`enter`. Match a reply only when the reply belongs to the same pair. The reply carries only the query, so
  record the `scope_row_of` the in-flight search was sent with and drop the reply when the overlay's current pair no
  longer matches it. `cycle_project` (~:421) clears `sent` and the hits, as a scope change should.
- Tests (overlay unit tests, with a one-member scope and a non-nil workspace):
  - "all" search answered, then `Ctrl+P`: Enter sends a new search with `scope_row_of: None` and emits no `Reveal`.
  - A reply to the "all" search arriving after `Ctrl+P` is dropped.

## L1 — a document can be left half-indexed
`crates/htui-store/src/vector_sync.rs` `sync_owner_documents` (~:208-226): a latest owner document counts as in step
when *any* point with its `document_id` exists, but its points are upserted in `UPSERT_BATCH` (256) chunks. A failed
later chunk (a Qdrant timeout on the first rebuild after the stamp bump) leaves the document's remaining sections
missing until a new version is written.
- Fix: upsert each document's points in one call, as the item pass does (one upsert per item). If you keep any
  batching across documents, never split one document across two calls. Either way, keep the "in step = has points"
  check sound. Optionally (cheap, no embedding) treat a document as in step only when its stored point count equals
  `chunk_markdown(body, MAX_CHUNK_CHARS).len().max(1)`. Do it if it stays simple.
- Test (MemStore + MemVectorStore): a latest owner document with some of its points missing from the index (delete
  one section's point by `document_point_id(id, 1)`) is rebuilt by the next sync when you add the count check. Without
  the count check, test that one document's points always arrive in one `upsert` (e.g. a `MemVectorStore` upsert
  counter, `upserted()`, if it counts calls).
