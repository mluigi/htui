## F1 (high) — the Unblock land and the sweep can push one record twice

`crates/htui-worker/src/runtime.rs` `unblock`, the `RetryLanding` arm (~3741-3762), calls
`engine.land(Some(run))` in the unblock task, which registers no walk. That engine uses the process-wide
lease owner, the same one the sweep's land arm (`land()`, ~2325-2370) uses, and `take_integrations`
re-takes a `pending` record already leased to the same owner (`pg/write.rs` ~10734: `lease_owner = $2 OR
…`). M1 kept the walk's own land and the sweep apart only through `ctx.shared.walks.is_live(run)` (the
sweep skips live walks). So a sweep tick during the unblock's `git push` can take the same record and push
concurrently; the losing push can settle `refused` first and the real success then answers `false`.

Fix: hold a walk token for the run across the in-task land (`ctx.shared.walks.child(run)` or whatever the
walk registry's API is — read it; mirror how a walk's own Finished land is protected), so the sweep's
`is_live` filter skips the run. Test (worker, `crates/htui-worker/tests/it/`, the M1/M2 landing module): a
sweep run while the unblock's land is in flight (a scripted slow land / a gate the test holds) lands
nothing for that run, and exactly one land request is made.

## F2 (medium) — `Q` queues an item that is still landing

`crates/htui/src/ui/tabs/backlog/queue.rs:25` `toggle_queued` refuses only `ItemState::Done | Closed`. A
done-not-landed item used to read `Done`; it now reads `Landing`/`LandRefused` and is queued, and then sits
as "not ready" forever (`ready_items` never admits an item with a graph run). Fix: refuse when
`state.is_finished() || state == ItemState::Closed` (keep the refusal wording sensible for the new states).
Test: a list-level test with a `Landing` and a `LandRefused` summary, mirroring the existing `Done` test.

## F3 (low) — the retry arm re-derives the Unblock case without the run lock

`runtime.rs` ~3742: the `RetryLanding` arm calls `engine.dispatch(Command::Unblock)`, which re-derives the
case; if a write in between moved it to `Resume`/`FollowRun`, that case runs without the run lock and its
checks. Fix: in the `RetryLanding` arm call T4's `Engine::retry_landing` for exactly that run (no
re-derivation), and build the `Unblocked` outcome as the dispatch would; keep a stale press answering the
`nothing_is_refused()` refusal. Do not change the `Reopen` arm.

## F4 (low) — the conformance lease assertion is vacuous

`crates/htui-core/src/store/conformance.rs` ~22179: `settle_integration` already clears the lease when it
refuses, so "another owner takes it after the retry" passes even if `retry_landing` cleared nothing. A
refused row cannot hold a lease through the public API. Fix: drop the lease claim from the case's doc and
assertion message (keep the "it is pending and takeable again" check, worded as such); do not add a
store-specific back door.

## F5 (low) — Settings > Prompt: a stored `local` cannot be cleared without a remote

`crates/htui/src/ui/tabs/settings/prompt.rs` `cycle_integrate` (~473-494): the cycle is not set → local →
push → not set; with no remote the step to `push` is refused, so `local` can never go back to not set.
Fix: when `push` is refused, step to the clear instead (still show the refusal in the notice). Also fix
the doc comment's contradiction about unreadable values (the code replaces them with `local`). Test in
`crates/htui/tests/it/prompt_settings.rs`: on a project with no remote, local → (press) → not set, with
the refusal shown.
