### Decisions this plan takes

- **P1 — Migration `0037_execution_targets.sql`, cache migration `0013_execution_targets.sql`.**
- **P2 — The seed.**
  - `crates/htui-core/src/seed.rs` holds two constants:
    - `pub const LOCAL_TARGET_ID: TargetId = TargetId::from_uuid(Uuid::from_u128(0x0000_0000_0000_4000_8000_0000_0000_0001));`
    - `pub const LOCAL_TARGET_NAME: &str = "this box";`
  - `0037` inserts that row. MemStore seeds the same row when its state is built.
  - A migrations test pins the migration's row equal to the constants, as `0021`'s project types are
    pinned to `seed::PROJECT_TYPES`.
- **P3 — The `os_family` CHECK.** A plain `os_family IN (…)` passes on `NULL`, so the CHECK is written
  `CASE WHEN os_family IS NULL THEN kind = 'container' ELSE os_family IN ('windows','linux','macos') END`.
- **P4 — Who binds a box.** Only `attach_child_box` sets `target.box_id` in M1 (a `docker` target only).
  `NewTarget` has no box. MOD-131 adds the ssh binder.
- **P5 — Child box values.** A child box is inserted with:
  - the parent's `user_id` and the caller's `hostname`;
  - `os_family NULL`, `os_version ''`, `arch ''` and `htui_version ''`, so MOD-44's first probe always
    runs;
  - empty tags and `edit_version 0`.
  `BoxRow.os_family` becomes `Option<OsFamily>`, and so does `BoxProfile.os_family`. The render omits
  the OS line on `None`. `BoxInfo` (this box, always a machine) keeps `OsFamily`, and its Pg read uses
  the `"os_family!: OsFamily"` override.
- **P6 — Compare-and-set tokens.**
  - `target`, `project` and `step_graph` use `updated_at`, as `update_project` and `update_step_graph`
    do.
  - The Settings default uses the row's `updated_at`, with `None` meaning "I expect no row", exactly as
    `set_box_probe_spec` does.
  - The item uses `version` (D11).
  - Each setter is its own method, so `ProjectPatch` and `StepGraphPatch` do not change.
- **P7 — The cache mirror.**
  - Only this box is mirrored (`refresh_box` deletes the others), and this box is a machine. The mirror
    `box` table therefore stays unchanged.
  - The mirror gains a `target` table (a full replace, like `replace_workspace`), `project.target_id`,
    `item.target_id`, `run.target_id` and `run.target_source`.
  - `step_graph` is not mirrored.
- **P8 — Run history on MemStore waits for M2.** M1's `Run` has no `target_id`, so only Pg can see run
  history. Pg's `delete_target` refuses on run history now, and a `pg_criteria` test proves it. Mem's
  branch and its conformance coverage land with M2's `Run.target_id`.
- **P9 — Refusal sentences** are `#[must_use] pub fn … -> String` in `crates/htui-core/src/store/traits.rs`,
  beside `link_outside_reach`. They are returned as `StoreError::Constraint(sentence)`. A missing row is
  `StoreError::NotFound { entity: "target" | "box" | …, id }`. Neither store ever surfaces a raw
  SQLSTATE: `ON DELETE RESTRICT` is `23503` on PG 16 and `23001` on PG 18, so every refusal is checked in
  code before the statement runs. The sentences:
  - `target_built_in()`: "the local target is built in; it cannot be created, edited, retired or deleted"
  - `target_name_taken(name: &str)`: "a target named {name} exists"
  - `target_name_refused(name: &str)`: "a target name is 1-64 characters with no control character; {name:?} is not"
  - `target_locator_refused(why: &str)`: "a target locator holds names and addresses, never secrets: {why}"
  - `target_retired(name: &str)`: "target {name} is retired"
  - `target_in_use(name: &str, users: &[String])`: "target {name} is used by {users joined with ", "}; set them to inherit or another target first"
  - `target_has_runs(name: &str, runs: u64)`: "target {name} has {runs} run(s); retire it instead"
  - `target_not_docker(name: &str, kind: TargetKind)`: "only a docker target takes a container box; {name} is {kind}"
  - `target_bound_elsewhere(name: &str, other: BoxId)`: "target {name} is bound to box {other}"
  - `child_box_needs_a_machine(parent: BoxId)`: "box {parent} is a container; a child box needs a machine parent"
  - `box_not_a_child_of(child: BoxId, parent: BoxId)`: "box {child} exists and is not a container of box {parent}"

  A "user" (in `target_in_use`) is labelled `project <slug>`, or `workspace <slug without @>` for a
  scope row; `workflow <name>`; `item <key>`; or `Settings default`. The labels are sorted by bytes.
- **P10 — Read order.** `targets()` orders by `name` byte order: Pg `ORDER BY name COLLATE "C", id`,
  Mem a byte sort. Retired targets are included; pickers filter them later.
- **P11 — No `StoreRequest`, no TUI surface (D16).** The new methods sit on the store traits and are
  exercised by conformance cases only. The one TUI edit is the item spec field (T3), because the item
  form and the divergence view compile against `ItemSpec` and `SpecField`.

### Task 2: Targets are created, edited and bound to a child box

**Depends on:** T1. **Files:** `traits.rs`, `mem.rs`, `conformance.rs`, `pg/write.rs`, `writer.rs`,
`htui-agent/src/conformance.rs`, `htui-agent/tests/it/recorder.rs`, `pg_conformance.rs`,
`mem_store.rs`, `.sqlx`.

**Model (`model/target.rs`):**

```rust
pub struct NewTarget { pub id: TargetId, pub name: String, pub kind: TargetKind, pub locator: Value }   // P4: no box
#[derive(Default)] pub struct TargetEdit { pub name: Option<String>, pub locator: Option<Value> }       // kind and box never edited
pub struct NewChildBox { pub id: BoxId, pub parent: BoxId, pub hostname: String, pub target: TargetId }
pub struct AttachedBox { pub child: BoxRow, pub target: Target }
```

**`WriteStore` methods**, implemented on Mem, Pg, Writer, UsageSpy and SpyStore. They are not on
`WorkerStore`:

```rust
async fn create_target(&self, new: NewTarget) -> Result<Target>;
async fn edit_target(&self, id: TargetId, expected: DateTime<Utc>, edit: TargetEdit) -> Result<CasOutcome<Target>>;
async fn attach_child_box(&self, new: NewChildBox) -> Result<AttachedBox>;
```

**`create_target` refusals, in order:**
1. `kind == Local` → `target_built_in()`.
2. `target_name_refusal`.
3. `locator_refusal` → `target_locator_refused`.
4. Name taken → `target_name_taken`. Check this before the INSERT; Pg must never surface `23505`.

`create_target` is idempotent on `id` when every field is equal: it returns the stored row, as
`create_project` does.

**`edit_target` refusals, in order:**
1. NotFound `target`.
2. Local → `target_built_in()`.
3. The name and locator refusals as above.
4. `Stale(current)` when `expected` is not the row's `updated_at`.
5. A name taken by another target → `target_name_taken`.

A retired target can still be edited.

**`attach_child_box` refusals, in order:**
1. NotFound `target`.
2. Retired → `target_retired`.
3. `kind != Docker` → `target_not_docker`.
4. NotFound `box` for the parent.
5. The parent is a container → `child_box_needs_a_machine`.
6. `id` exists and is not a container of `parent` → `box_not_a_child_of`.
7. `target.box_id` is `Some(other)` with `other != id` → `target_bound_elsewhere`.

Then it inserts the child (P5) unless it exists, and sets `target.box_id = id` unless already set. A
repeat returns the same `AttachedBox` and writes nothing: the target's `updated_at` does not move. On Pg
it is one transaction and takes `SELECT … FROM target WHERE id = $1 FOR UPDATE` before checking.

**Tests first.** Four conformance cases, registered in `CASES` and `run_case_inline`:
- `create_target_round_trips_every_kind_but_local`:
  - Create docker, ssh, ssh_docker and enrolled targets.
  - `targets()` lists local plus the four in name byte order.
  - Each status is `Planned` (D1).
  - `target(id)` equals what `create_target` returned.
  - A repeat create is idempotent.
- `create_target_refusals`: each P9 sentence, compared exactly with `constraint_exactly`
  (`conformance.rs:23301`, signature `(case, outcome: Result<T, StoreError>, sentence, what)`), in the order above, and nothing written.
- `edit_target_is_cas_on_updated_at`:
  - Rename and change the locator → Applied, and `updated_at` moves.
  - A spent token → `Stale(current)`.
  - Editing the local target → `target_built_in`.
  - A name clash → `target_name_taken`.
- `attach_child_box_creates_reuses_and_refuses`:
  - The child has `kind container`, the parent, `os_family None`, `htui_version ""` and the parent's
    user, and the target's `box_id` is set.
  - A repeat makes no write (`updated_at` unchanged).
  - Each refusal 1, 3, 4, 5, 6 and 7 fires. Refusal 2 is covered in T4, after retire exists.
  - `boxes()` now lists the child.

**Pins moved:** the case count goes from 325 to 329 in both files. `.sqlx`.

## Blueprint deltas that apply to this task (accepted; they supersede the task text)

## B2 — T2: `create_target` on a taken id is refused; it is not idempotent

**What.** Plan :415-416 says `create_target` is idempotent on `id` "as `create_project` does", and
test :446 says "A repeat create is idempotent".

**Why.** `create_project` is not idempotent. Mem refuses a stored id with "project `{id}` already
exists" (`mem.rs:3467-3472`), and Pg relies on the `23505` mapping (`pg/write.rs:4178-4180`). The
house sentence for a client-minted id that is already stored is `already_exists(entity, id)`
(`traits.rs:3658-3662`). The plan also leaves undefined what an equal id with different fields gives.
The local target's id with a non-local kind is such a case, and it falls through refusal 1.

**Replace :415-416 with:** "A taken `id` (the local target's included) is
`StoreError::Constraint(already_exists("target", id))`. It is checked after the input refusals 1-3
and before the name check, and Pg checks it in code before the INSERT."
**Replace test :446 with:** "A repeat create gives `already_exists("target", id)` exactly and writes
nothing; `create_target` with `id = LOCAL_TARGET_ID` and kind `docker` gives the same."


## B3 — P9, T2-T4: a reference that names no row is `references_no_row`, not `NotFound`

**What.** P9 says "A missing row is `StoreError::NotFound { entity: "target" | "box" | … }`". It is
applied to the target named *by* a level (T3 :506, T4 "Refusals shared by the three setters") and to
the parent box of `attach_child_box`.

**Why.** The house rule keeps `NotFound` for the row the method addresses, and uses
`Constraint(references_no_row(column, id, table))` (`traits.rs:3645-3649`) for a foreign key in the
input that names no row. Examples: `create_step_graph` (`traits.rs:1018-1024`) and `replace_graph`
(`:1143-1145`). `update_item` refuses an unknown kind as a `Constraint` too, after the version compare
(`mem.rs:2524-2540`). T3 also names a writer that does not exist: the item insert is `mint_item`
(`traits.rs:418`; Mem `State::mint`). `update_item`'s stale outcome is `UpdateOutcome::Diverged`, and
it comes before every refusal (`mem.rs:2511-2522`).

**Replace P9's NotFound sentence with:** "`NotFound { entity, id }` is for the addressed row only: the
`target` of `target`/`edit_target`/`retire_target`/`delete_target`/`attach_child_box`, the `project`
of `set_project_target` and the `step_graph` of `set_graph_target`. A target id carried as a value
that names no row is `Constraint(references_no_row("<table>.target_id", id, "target"))`, with column
`item.target_id`, `project.target_id`, `step_graph.target_id` or `app_setting.default_target`.
`attach_child_box`'s missing parent is `references_no_row("box.parent_box_id", parent, "box")`."

**Replace T3's "Store." paragraph's first sentence with:** "`mint_item` and `update_item` write
`target_id`. In `update_item` the target refusals run after the version compare (`Diverged` first)
and after the kind check, in the block that opens at `mem.rs:2524`, so nothing is half-applied."
Test `item_target_is_a_spec_field`: "an unknown target → `references_no_row("item.target_id", …)`";
"a spent version → `UpdateOutcome::Diverged`".


## B4 — P9: house spelling, the name trim, and NUL in the locator and the hostname

**What.** (a) `target_name_taken` reads "a target named {name} exists". (b) `target_name_refusal`
"trims", but it returns only a refusal, so it cannot store a trimmed name, and the plan does not say
which name is stored. (c) No rule refuses a NUL in `locator` or in `NewChildBox.hostname`.

**Why.** (a) The house form for a unique name is "`<table>.<column> `{value}` is taken`":
`graph_name_is_taken` (`traits.rs:3696`) and "project.slug `{}` is taken" (`mem.rs:3473-3476`).
(c) Postgres `jsonb` refuses `\u0000` with `22P05` and `text` refuses NUL with `22021`. `map_sqlx`
maps every non-`23` code to `StoreError::Backend` (`error.rs:41-46`), so Pg answers a backend error
where Mem stores the row. That breaks P9's "never a raw SQLSTATE" and the conformance parity. The
house rule exists for this case: `json_has_nul` (`traits.rs:3181`) and `has_nul` (`:3392`), used by
`run_plan_refusal` (`:3156-3177`).

**Replace in P9:**
- `target_name_taken(name)`: "target.name `{name}` is taken".
- `target_name_refused(name)`: "target.name is 1-64 characters with no control character and no
  leading or trailing space; {name:?} is not". The name is stored as given, never trimmed, and
  `name != name.trim()` is refused, so both stores compare and store the same bytes.

**Add to `locator_refusal` (T1), first:** `json_has_nul(locator)` → `has_nul("target.locator")`.
Make `json_has_nul` `pub(crate)`, or put `locator_refusal` in `traits.rs` beside `run_plan_refusal`.
**Add to `attach_child_box` (T2) as refusal 0, before any read:** `hostname` empty or containing NUL →
`has_nul("box.hostname")` (or a blank-hostname sentence). Add both to the refusal cases.


## B5 — P9: the in-use labels are ambiguous across projects

**What.** `workflow <name>` and `item <key>` (P9 :105-107).

**Why.** Every project is seeded with graphs of the same names: "`item_kind.name`, which is also
`step_graph.name`" (`seed.rs:47-48`). Graph names are unique per scope only (`graph_name_is_taken`,
`traits.rs:3694-3698`). Item keys are unique per project only. A target used by the `feature` graph of
two projects reads "workflow feature, workflow feature", and the person cannot find either.

**Replace the label sentence with:** "A user is labelled `project <slug>`; `workspace <slug without
@>` for a scope row; `workflow <name> of project <slug>` | `of workspace <slug>` | `in the library`;
`item <key> of project <slug>` (the scope row's slug without `@` for a workspace-owned item); or
`Settings default`. Labels are deduplicated and sorted by bytes."


## B7 — T2-T4 (Pg): retire and the level setters race; lock the target row

**What.** Only `attach_child_box` takes `FOR UPDATE` on the target. `retire_target` checks "in use"
and then writes `retired_at`. `set_project_target`, `set_graph_target`, `set_default_target`,
`mint_item` and `update_item` check "not retired" and then write.

**Why.** Two concurrent transactions can each pass their check. Then a level names a retired target,
which D14 forbids. No foreign key guards retire, and an FK check takes `FOR KEY SHARE`, which does
not conflict with an UPDATE of `retired_at`. The same race on delete reaches the FK and comes back as
`map_sqlx`'s raw "fk_…: …" `Constraint` (`error.rs:37-44`), not a P9 sentence.

**Add to P9, after "checked in code before the statement runs":** "On Pg, every writer that names a
target as a value reads it with `SELECT retired_at FROM target WHERE id = $1 FOR SHARE` in its own
transaction, before its check. `retire_target`, `delete_target` and `attach_child_box` read it with
`FOR UPDATE`. A setter that waits behind a retire sees `target_retired`, and one that waits behind a
delete sees `references_no_row`. Mem is serial under its write lock." Add one `pg_criteria` test,
`a_level_set_behind_a_retire_is_refused`: two connections, retire holding the lock, then the setter
gives `target_retired`.


## B10 — P4, T1 rule 6, T2: model `ssh_docker` like `docker` (a container child), one target per container (recommended)

**What.** Rule 6 takes `host` = "its parent (docker) or itself (ssh_docker)". So an `ssh_docker`
target binds the remote *machine*, and `attach_child_box` accepts `Docker` only. Also, a container box
already bound to another target can be attached again (refusal 6 checks only the parent).

**Why.** D9 checks tags and agent candidates on `target_box_id` "because the toolchain and agents are
inside the container", and D12 says "only a container is a child". A remote docker's container is a
container on the remote machine, so its box is a child of that machine (MOD-131 registers the
machine). Under the plan's shape, M3's tag check for an `ssh_docker` run would read the remote host's
tags instead of the container's, and MOD-131 would have to change `status`'s host rule,
`target_not_docker` and P4. The PRD risk table assumes one container box per image (one per target).
