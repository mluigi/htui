## Findings to fix

1. **MEDIUM - attach races with delete on Postgres** (`crates/htui-store/src/pg/write.rs` ~:6848 existence check on the pool, ~:6976 INSERT, `delete_mcp_server` ~:7245). The check and the INSERT are separate statements, so a concurrent delete that commits between them leaves an `mcp_server` binding row naming nothing (it then cannot be detached from the UI and every `override_graph` of that phase is refused). Fix: do the existence check and the INSERT in one transaction, taking `SELECT 1 FROM mcp_server WHERE id = $1 FOR KEY SHARE` before the INSERT (`delete_mcp_server` already deletes the server first, the bindings second, so the locked order serialises). Add a test that runs the two interleavings you can deterministically produce (delete committed before attach: attach refuses with the not-found sentence; attach in flight then delete: no orphan row remains). If a real race cannot be forced, test the ordering through a transaction hook you can reach and say so.
2. **MEDIUM - the id pun** (`Binding.skill_id: SkillId` holds a server's id for `mcp_server` rows; `BindingKey::of` in `model/skill.rs` ~:306 always yields `BindingRef::Skill`). Putting a kind on `Binding` is DEFERRED (wide change). Do instead: (a) `create_mcp_server` in both stores refuses an id that is already a skill id, and skill creation refuses an id that is already a server id (same refusal family and sentence helper as a taken id; Mem under its one lock, Pg inside the create statement/transaction); (b) correct the doc of `BindingKey::of` and of `Binding.skill_id` to say a row of kind `mcp_server` holds the server id there and that callers must tell kinds by `target`/lookup; (c) conformance: extend `a_skill_and_a_server_of_one_name_do_not_collide` (`store/conformance.rs` ~:17554) so its body does what its doc says (detach each row, prove neither delete nor detach touches the other's rows) and add the same-id refusal case, on Mem and Pg.
3. L1 - `store/traits.rs` ~:1346-1349: the doc gives the wrong refusal order for `create_mcp_server` (unknown `created_by` is checked first in both stores). Fix the doc; make the conformance case assert the order (a request with an unknown creator and a taken name refuses with the creator sentence).
4. L2 / (orch review 5) - credentials in `url` and control characters (`crates/htui-core/src/model/mcp.rs` ~:276, ~:351): refuse `url` with userinfo (`user:pass@`) and secret-looking query keys (`token`, `secret`, `key`, `password`, `passwd`, `pwd`, `credential`, `authorization`, `cookie`, `api_key`, `apikey`, `access_token`: match on the lower-cased query key containing any of the D3 words); refuse ASCII control characters (CR, LF, NUL ...) in `url`, header values and header names.
